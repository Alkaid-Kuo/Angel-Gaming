# BUGS.md：引擎漏洞與規格不清之處

本次開發沒有發現需要利用的引擎漏洞，也沒有利用任何漏洞（選手只使用觀察資料與 helpers）。以下是實際遇到的規格不清或容易誤解之處：

1. **主礦總量只有 4000（4 個礦點 × 儲量 1000）**（已實測確認）
   規格書「地圖物件」只寫了礦點儲量，沒有點出後果：不擴張的選手在約 tick 4000 後經濟歸零（實測雙方 `gathered` 都停在 4000 上下、對局拖到時限時雙方都沒有收入）。建議在「經濟」章節明講，或在選手 API 提供各礦區剩餘總量（目前要自己加總 `mineNodes[].reserve`）。
2. **建造的扣款時機（工人抵達時）容易讓選手超支**（規格已寫，但容易漏看）
   規格寫了「下指令時不檢查礦量、抵達時才扣款」，但 `obs.minerals` 沒有扣掉「已下令、未抵達」的預訂金額；連續下令的選手必須自己保留礦，否則會 `buildFailed(NO_MINERALS)`。建議在觀察資料補一欄預訂金額，或在規格書用醒目方式說明。
3. **統計欄位 `firstDamageTick` 的定義不明**
   README 只列出欄位名稱。1v1 實測雙方的值很接近但不同（例如 2482 與 2457），看不出是「該選手造成傷害」還是「該選手受到傷害」的第一個 tick。
4. **（未驗證的疑問）`rememberedBuildings` 在建築被摧毀後的清除時機**
   規格寫「看到該處已無建築時才會消失」。若部隊在遠處（超出視野）把建築打掉，記憶是否仍殘留已被摧毀的建築，我沒有針對這點做專門測試；選手若拿記憶建築當進攻目標可能被舊資訊誤導，建議規格說明。
5. **`attack` 指令的目標必須「看得到」，而 `attackMove` 沒有「優先打建築」的選項**（API 使用陷阱，非漏洞）
   要集火主堡只能等它進入視野後下 `attack`；單位在 `attack` 期間不會回擊攻擊自己的單位，所以選手要自己拆分「應對威脅的單位」與「打建築的單位」。建議在規格的「指令與自動行為」段落補一句提醒。
