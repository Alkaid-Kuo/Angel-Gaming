# CS 射擊 Bot 3.0 第一步：資源層（乙）設計（2026-11-07 審過）

依據：路線圖 `docs/2026-11-06_CS射擊_Bot3.0路線圖.md` 第六節。分支 `claude/cs-bot-3-0`。2026-11-07 審查端審過，第十節是五個決定，第十一節是三點補充。

## 一、範圍

**做**：
- 道具計畫。
- 需求表與依表購買。
- `claim` 與重新分配。
- 閃光的跟進者觸發。
- 回防必走道具，連同 3.0 驗證清單 (a) 的換入口。

**不做**：
- 效用層、指揮層重寫。
- 驗證清單 (b)～(d)，留給丙-1。

其他行為照 2.8，包括戰術選擇、站位、交戰、經濟喊法。

**不維持「和 2.8 逐場相同」**：升版本來就要改行為。試玩頁 v1～v5 都用同一支產物，等級表會一起變，定版時重量。

## 二、架構

新增模組 `bots/shooter-src/resources.js`，`class Resources`：
- 每個 Bot 各持一份副本。
- **指揮者**（沿用 `commanderOf`：活著的最小 id）寫，全隊讀。
- 狀態只由隊內喊話決定，所以每份副本一致。指揮者陣亡後，新指揮者直接接手寫。

隊友身上的道具**不公開**（`TeammateInfo` 沒有 loadout），所以要喊持有。隊友金錢公開，可以用來排購買。

### 喊話協定（新增 `U:` 前綴，每則 ≤ 120 字）

| 何時 | 誰喊 | 內容 | 例 |
|---|---|---|---|
| 凍結第 1 次決策，與 `B:` 同一批 | 指揮者 | 購買單：誰要先買哪些道具 | `U:b 3:ff 5:s 7:sm` |
| 買完的下一次決策 | 每人 | 自己的持有 | `U:h ffsm`（f 閃、s 煙、h 手雷、m 燃燒瓶或燃燒彈） |
| 全員 `U:h` 收齊後，或凍結剩 1 秒 | 指揮者 | 道具計畫 | `U:p fa3A0 fa5A0 sb7A0` |
| 丟出時，和既有 `E:flash`／`E:smoke`／`E:burn` 一起 | 丟的人 | 用掉第幾筆 | `U:u 2` |
| 擁有者到期還丟不出去 | 擁有者 | 放棄，帶原因碼（s＝找不到安全點、r＝丟不到、t＝逾時） | `U:x 2 s` |
| 擁有者陣亡、放棄、回防開始 | 指揮者 | 重新分配給誰，或作廢 | `U:r 2 7`／`U:r 2 -` |

**計畫 token**（5 字元）：
- 種類 1 字、用途 1 字、擁有者 id 1 字、目標 2 字（包點＋入口序號；`S` 表示包點內架點）。
- 例：`fa3A0` 是閃光、entryFlash、3 號、A 點 0 號入口。
- 觸發條件由用途決定，不另外喊。
- 序號就是 token 的順序。
- 上限 19 筆。全隊最多 5 人 × 4 格，計畫只列有用途的道具，實際約 3～8 筆。

**購買時序（補充 A）**：
- 指揮者在凍結第 1 次決策喊 `B:`、`U:b`，自己也在這次買。
- 隊友**一定在收到 `U:b` 之後**才買，也就是第 2 次決策起；不能和指揮者第 1 次決策同一個 tick 買。
- 現行規則「等指揮者 1 秒，沒等到就自己買」保留，當成沒收到 `U:b` 時的退化。
- 測試證明購買單生效：每人買到的道具和 `U:b` 指定的相同。

**時間**：決策間隔 3 tick，Bot 賽制凍結 3 秒。上面四步約 4 次決策（0.6 秒），凍結內完成。

**退化（保險）**：
- 到 live 開始仍沒收到 `U:p`（例如混隊、隊友是陪練 Bot）：全部道具視為 free，各用途照 2.8 的觸發丟。
- 隊友沒喊 `U:h`：視為沒有道具。

## 三、資料結構

```js
/** @typedef {'entryFlash'|'entrySmoke'|'holdSmoke'|'fireBackup'|'fakeUtil'|'chokeMolotov'|'retakeSmoke'|'retakeFlash'|'free'} Purpose */
/** 目標：包點＋入口序號；ent = -1 表示包點內架點（smokeTarget／flashPoint 解析成座標） */
/** @typedef {{ site: SiteId, ent: number }} Target */
/** @typedef {{ on: 'follower', who: number } | { on: 'exec' } | { on: 'fire' } | { on: 'fakeStage' } | { on: 'contact' } | { on: 'retake' } | { on: 'any' }} Trigger */
/**
 * @typedef {{
 *   idx: number, owner: number, kind: GrenadeId, purpose: Purpose, target: Target, trigger: Trigger,
 *   prio: number,                      // 需求表裡的順位（重分配、搶同一顆時用）
 *   state: 'plan' | 'used' | 'lost',
 *   freeAt: number                     // 到這個 tick 還沒觸發就轉 free（-1＝不轉）
 * }} UtilItem
 */
/** @typedef {{ purpose: Purpose, kind: GrenadeId, target: 'exec'|'main'|'second'|'fake'|'choke'|'retake', role: number[], must: boolean }} Need */

class Resources {
  reset()                                         // 每回合
  needs(plan, call, team) -> Need[]               // 需求表（第四節），純函式
  buyOrders(obs, plan, call) -> Map<id, GrenadeId[]>  // 指揮者：依 Need 的 must 列、公開金錢、角色排
  allocate(obs, plan) -> UtilItem[]               // 指揮者：依 U:h 持有配 owner
  read(chat)                                      // 全員：吃 U:b／U:h／U:p／U:u／U:x／U:r
  upkeep(obs, out)                                // 指揮者：陣亡、放棄、回防開始時重分配，喊 U:r
  claim(playerId, kind, purpose) -> UtilItem|null // 個人層：擁有者是自己、state=plan、用途相符（或 free）才給
  due(obs, item) -> boolean                       // 觸發條件成立（第五節）
  used(idx) / giveUp(idx)                         // 個人層丟出、放棄
}
```

**`claim` 語意**：
- 回傳自己這種道具中、用途相符、順位最前的那筆。沒有就回 null，個人層就不丟。
- `purpose` 給 `'free'` 時只拿 free 的那筆：計畫外的道具，或已經到期轉成 free 的。
- **保留不出借**：fireBackup、retakeSmoke、retakeFlash 在到期前，不能被其他用途拿走。

**`Utility` 要改的地方**：
- 現在每種道具每人每回合只丟一次（`used` 是種類集合），兩顆閃光只丟得出一顆。
- 改成依持有數量扣減，`has()` 看「持有數 − 已丟數 > 0」。

## 四、需求表

**欄位意思**：
- **必**＝必要列。指揮者照它下購買單；錢不夠時從表尾的列開始刪。
- **選**＝選用列。只用已有的道具填，不下購買單。

**通用規則**：
- 購買單外，每人照原本角色的 `UTIL` 順序補到滿。這些多出來的道具，進計畫時都是 free。
- 擁有者依「角色偏好」挑，同條件依金錢多、id 小。
- 買法：
  - eco：不下購買單。
  - force：只下 entryFlash 一列，最多一顆；其他用途只用已持有的道具填。
  - half：沿用 2.8，不下購買單。

### 跟進者觸發（解隊友致盲，第六節第 4 條）

1. **誰是跟進者**：該組的突破手（組內序號 0）。陣亡就依序往後找。
2. **何時丟**：跟進者到入口外點 `ent.o` 的距離 ≤ N 格，**以跟進者的位置算，不是以丟的人的位置算**。
   - N ＝ `routeSpeed` ×（閃光引信 1.5 秒＋反應 tick）＋ 1。
   - 目的是炸開時跟進者剛好在入口外。
3. **選爆點時加「炸開時安全」**：
   - 預測每個活著的隊友在炸開那個 tick 的位置：跟進者在 `ent.o`；其他人從目前位置朝他們的目標走，最多走 `routeSpeed` × 引信秒數。
   - 用引擎的致盲公式（正面 ≤ 60° 2 秒、側面 ≤ 120° 1 秒、背面 0.3 秒，乘距離係數）估。
   - 要求每個隊友「沒視線」或「在背面範圍」。
   - 找不到這樣的點就延後 1 個決策窗口；跟進者觸發超過 3 秒還不成立，就放棄（`U:x`）。
4. **跟進者等閃**：收到 `E:flash` 且還沒炸開時，跟進者如果下一步會進入爆點的視線，就停在入口外線（沿用 2.8 `pending` 的停法，條件改成視線）。
   - 最多等到炸開後 0.1 秒。
   - 現行 `flashSafe` 只檢查丟出那一刻的隊友位置；炸開前 1.5 秒內衝進視線的跟進者，正是 default 致盲 40% 的來源（實作第一步先用 `blind.mjs` 拆解確認）。

### 回防（第六節第 5 條，驗證清單 (a)）

- **包下時**指揮者重分配 retakeSmoke、retakeFlash：給活著、身上有該道具、離包點路程最近的人，喊 `U:r`。
- **進點入口**：預設是現行回防入口；**被敵方煙蓋住就換另一入口**（清單 (a)）。retakeSmoke 改封沒選的那個入口。
- **進點閘門**：
  - 回防組要等 retakeFlash 炸開或 retakeSmoke 散開才一起進。
  - 例外：兩顆的擁有者都陣亡或放棄，或炸彈剩餘時間 <（拆彈時間＋路程＋2 秒），就直接進。
- **不必走道具的情況**：一人回防而且身上沒道具，照 2.8。

## 六、重新分配規則

- **擁有者陣亡、放棄（`U:x`），或凍結時買不到**：
  - 交給「活著、身上有這種道具、手上那顆沒被更高順位佔用」的人裡，到目標路程最短的；同距離取 id 小。
  - 沒有人就作廢（`lost`）。
- **用掉**：`used`，不補。
- **回防開始**：只重分配兩顆 retake 道具，規則同上。
- **free**：不重分配，擁有者就是持有人。
- 只有指揮者喊 `U:r`，所以不會兩個人搶同一顆。

## 八、確定性與大小

**確定性**：
- 新邏輯全部確定性，同分取 id 小。
- 沒有 `h.random()`，也不用 `Math.exp` 之類。
- 喊話多了 `U:` 幾則；引擎雜湊含聊天數，終局雜湊一定變。這是預期行為，測試裡相關的雜湊比對照前例處理成前提變更。

**大小**：
- 現在 233,711 bytes。估計 `resources.js` 和接線多 14～20 KB，到 248～254 KB。
- **上限已擴到 288 KB（294,912 bytes）**，使用者授權。
  - 唯一的寫死處：`src/config/index.ts` 的 `RULES.botModule.maxBytes`。它是全平台共用的，沙箱編譯、閘道、試玩頁、聯賽都讀這個值。
  - 測試 `test/shooter-ai.test.ts` 原本寫死 `256 * 1024`，改成讀 `RULES`。
  - `sandbox.test.ts` 本來就讀 `RULES`，不用改。

## 十、審查端決定（2026-11-07）
