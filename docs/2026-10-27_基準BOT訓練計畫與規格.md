## 〇、一頁摘要

**問題**：現在的基準 BOT（v1.68／v1.114／v1.159）是每一團各自獨立的反應規則，沒有戰場模型、沒有計畫層，因此做不出包抄、繞背、誘敵。訓練方式是 LLM 手寫規則再用勝率篩選，而訓練池多是正面硬上的對手，所以勝率天然選出盾弓龜陣；殲滅戰「時間到比戰果」又讓領先後龜縮成為理性行為。

**解法分三件事**：

1. **改模式**：殲滅戰拔掉，換成攻城戰（兩點依序、時間到守方勝），三場制「攻、守、佔點」。攻方角色逼 BOT 必須會機動，守方角色讓龜陣成為正當打法。
2. **改架構**：BOT 分三層——戰場模型（每秒）、機動計畫（每兩秒）、單團執行（每次決策）。機動是第一級概念，有進入條件、路徑點、放棄條件。
3. **改訓練**：先工程（手寫架構與機動庫、情境測試全過），再訓練（機動參數與選擇策略用自我對戰搜尋），再循環（對手池加入有形狀的對手）。勝率之外加行為指標。

**參考來源的取捨**：規則與地圖學戰意（攻城依序佔點、統御點數、野戰搶點），AI 架構學 Total War 與星海學術 Bot（兩層指揮、威脅圖、分隊任務），概念清單取軍事教範（錘砧、佯退、任務式指揮、OODA、蘭徹斯特），驗收情境取使用者回放。

## 一、前提：模式、地圖與城池（規格 v0.5 候選）

### 1.1 三場制

| 場次 | 模式 | 地圖 | 誰攻誰守 |
| --- | --- | --- | --- |
| 第一場 | 攻城 | 城池 | 甲攻乙守 |
| 第二場 | 攻城 | 城池 | 乙攻甲守 |
| 第三場 | 佔點 | 野地或大河谷（輪替） | 對稱 |

三場先取兩勝者勝；若一比一，第三場定勝負。殲滅戰模式自引擎移除，`mode` 只剩 `siege` 與 `capture`。全滅仍是任何模式的勝利條件（安全網），但不再是設計目標。

### 1.2 攻城戰規格

| 項目 | 規格 | 備註 |
| --- | --- | --- |
| 兩個旗點 | A ＝ 城門（門樓所在，旗圈半徑 5000）；B ＝ 本陣（內城） | 依序：A 未佔下前 B 不可佔 |
| 佔旗 | 沿用佔點模式進度條；圈內無敵兵且持續 **A 15 秒、B 30 秒（已定）** 即佔下 | A 在牆頂弓兵射程內，30 秒等於再吃一輪箭雨；B 給守方最後一次反撲。守方不能把 A 佔回去；A 佔下即永久 |
| A 佔下的效果 | 城門永久開啟；時限延長 **3 分鐘（試打後定）** | 第一批無後備；若試打後啟用攻方後備，入場點前移到 A 外側（戰意的「攻方重生點前移」） |
| B 佔下 | 攻方勝 | 勝因 `capture` |
| 時間到 | 守方勝 | 基礎時限 **8 分鐘（試打後定）** |
| 點數 | 攻守**對稱 600／600（已定）**，場上上限 600，**第一批無後備** | 600 ＝ 12 團，超過每次決策 10 條指令的上限，攻城要分衝車組、雲梯組、護衛、預備隊才夠分角色；佔點維持 500。使用者對「點數太少還是兵種太貴」未定，與 1.7 一起試打後看 |
| 平衡調節鈕 | 試打後：守方太強 → 啟用攻方後備、入場點隨 A 前移；攻方太強 → 啟用守方後備從 B 入場（引擎已有） | 兩個都先不開 |
| 砲擊支援 | 攻方指令 `bombard(x, y)`：下令後 **5 秒** 落地、半徑 **3 格**、敵我不分；每場 **3 發**、冷卻 **60 秒**；落點標記雙方可見；**不打城門、不打牆**；有牆後陰影區（見 1.3） | 數字待審。角色：清牆頂弓兵讓雲梯上得去，或留著打城內集結。使用者定：砲擊不轟門，免得與衝車重複 |
| 衝車 | 攻方免費 **1 台**、不計點；不會被摧毀；正面擋箭（遠程殺傷十分有限）；操作兵 ＝ 攻方任一步兵團附上（`man` 指令），移動速度最慢；貼門每 **3 秒**撞一下、**6 下**破門（已定，先測） | 守方只能出城擊殺操作兵（開正門、風險自控，與戰意同），所以守方只能延後、難以阻止破門。角色：衝車管時間、雲梯管空間、砲擊管火力 |
| 英雄 | 無 | 使用者決定 |
| 重生 | 無；攻城戰第一批連後備也無 | 兵力有限且公開，BOT 可以推算 |
| 守方布陣 | 城內與牆頂（`layer: 1`）皆可；攻方只能在地圖邊緣布陣區 | 守方可開局就架槍林、盾牆 |

### 1.3 城池機制（層索引方案）

引擎目前是單層格子：每格一個地形類型加一個高度，城牆與建築是不可走、擋視線的障礙。改法是**格子資料不變，士兵多一個整數 `layer`**，現在只用 0（地面）與 1（牆頂），之後塔樓多層可擴。

| 元素 | 規格 |
| --- | --- |
| 城牆格 `Wall` | 只有 `layer = 1` 的士兵可走；牆頂寬一格；牆頂高度 ＝ 地面高度 ＋ **3 階（已定）**，用在射程、傷害、視野的現有高度規則；牆的優勢來自「下面的人上不來」而不是數值。注意：每階 ＋10%、牆頂 ＋30% 增傷偏多，列入 1.7 試打後觀察 |
| 樓梯格 `Stair` | 城內側與牆相鄰的格；進入即切換 `layer`（0↔1），速度 ×50%；守方的上下牆通道 |
| 雲梯 | 攻方步兵（劍、盾、槍、輕步；騎兵不可）對相鄰城牆格下 `{ type: 'ladder', id, x, y }`，耗 **80 tick（8 秒，已定）** 架設，成為雙方皆可用的樓梯格；一團同時只能架一架，不限量，被推倒可再架 |
| 雲梯通過量 | 一把梯一次一人、每 **0.5 秒**上一人、爬到頂 **3 秒**（待審）；梯上同時約 6 人，一團 24 人約 15 秒全上；任何友軍可用任何梯；同一面牆可多梯 |
| 推倒雲梯 | 雲梯無血量。牆頂守方兵團站在梯口、梯口 **1 格**內無攻方士兵時可推，讀條 **3 秒（待審）**，期間被攻擊即中斷；推倒時梯上士兵摔落，傷害 ＝ 爬升進度 × **30%（待審）**（剛上梯幾乎不扣、到頂扣滿）。攻方反制 ＝ 第一批上牆的兵守住梯口（S30） |
| 門樓格 `Gatehouse` | `layer = 1` 永遠可走（牆頂連通）；`layer = 0` 在城門開啟或被破壞後可走 |
| 城門 | 有血量的物件，**只有衝車能扣**：6 撞 × 3 秒 ＝ 18 秒破門（已定，先測）；士兵攻擊與砲擊都不扣門血。守方可開門出擊、再關門（開關各 **3 秒，待審**），門開著時攻方可進 |
| 衝車物件 | 不可摧毀；有正面方向，正面 180° 內的箭矢被擋；附上的兵團跟衝車同速、脫離指令即卸下；只有一台 |
| 砲擊陰影 | 砲擊從攻方地圖邊緣方向飛來、拋物線落地：從落點往砲擊來向走 **4 格（待審）**內碰到 `Wall` 即為陰影區，不可落彈。所以砲擊打得到牆頂、門樓、城內深處，打不到門洞內側緊貼牆的槍林 |
| 側門與缺口 | 城池圖除正門外另有 1～2 條路線：側門（有血量、同城門規則但較薄）或城牆缺口（可走的斷牆格，無門）；攻方合計 **2～3 條路線**（使用者：太多守方難守） |
| 碰撞與目標 | 近戰、衝刺、碰撞、互擋只發生在同 `layer`；射擊可跨層，高度差照現有規則；牆頂視為擋住騎兵的地形 |
| 牆頂肉搏 | 允許，但牆頂只有一格寬，隘口縮窄規則會把隊形縮成縱隊；第一版先以「弓兵站牆頂、步兵守梯口」為主要用法，玩起來再決定要不要擴 |
| 畫面 | 觀戰網頁只做最低限度（牆頂士兵描邊或陰影位移、門樓畫拱門、穿門士兵半透明、衝車一個矩形、砲擊落點圓圈倒數）；正式畫面等 3D，`layer` 直接對應牆頂 y 座標 |

### 1.4 地圖與公開地圖特徵

第一批三張：

| 地圖 | 模式 | 特色 | 狀態 |
| --- | --- | --- | --- |
| 大河谷 240×150 | 佔點 | 三渡口三旗，現有 | 已有 |
| 平原（名稱待定）**待審** | 佔點 | 開闊、少障礙、騎兵有利；三旗 | 新做 |
| 城池（名稱待定）**待審** | 攻城 | 城池在一側，門樓朝攻方；正門之外另有側門或缺口，攻方共 2～3 條路線；城內有本陣高台；城外有一段開闊地與一處樹林（給攻方藏兵） | 新做 |

**BOT 不得一張圖寫一套。** 開局資料 `data.map` 新增 `features`，讓 BOT 從公開資料讀地形要點：

```
features: {
  walls:  [{ x0, y0, x1, y1, height }],   // 牆段
  gates:  [{ id, x, y, hp, kind }],        // 城門 kind: 'main' | 'side'；缺口列在 chokes（kind: 'breach'）
  stairs: [{ x, y }],                      // 樓梯格
  chokes: [{ x, y, width, kind }],         // 渡口、橋、坡道、門洞（kind）
  highs:  [{ x, y, radius, height }],      // 高地中心
  covers: [{ x, y, radius }],              // 樹林中心
}
```

觀察資料 `obs` 新增 `structures`（城門血量與開關、雲梯位置與架設進度、衝車位置與附上的兵團、砲擊落點與倒數、攻方剩餘砲擊數，雙方可見）；軍團觀測新增 `layer`。

### 1.6 不變項

視野與迷霧規則、決策 50 ms 上限、每次決策最多 10 條指令、單檔 ES2020、200 KB、`declare/init/deploy/decide` 介面、BOT 只用公開開局資料與可見資訊。基準 BOT **不作弊**。**使用者答（T8）**：資訊作弊（看穿迷霧、預知對方配兵）與數值作弊（加攻防當困難模式）**都不接受**，也不做「公平版＋作弊版」分級。強度只能來自戰術能力。

## 二、問題診斷（為何現有 BOT 沒有戰術）

看 v1.114 的程式碼，決策是每一團各自：找最近敵人 → 距離小於常數就攻擊、架槍、架盾或後退 → 否則往「最近敵人後方 8 格」走。約 20 個常數決定一切。包抄需要四樣東西，它一樣都沒有：

| 缺的東西 | 後果 |
| --- | --- |
| 敵軍整體的朝向與正面、側翼、背面扇區 | 不知道哪裡是「背後」，繞背無從談起 |
| 直線以外的路徑 | 只會直線接近，永遠正面撞上 |
| 友軍角色分工 | 沒有「你頂住、我繞」，每團都在做同一件事 |
| 等條件成立再動的時序 | 沒有「到位才衝」，衝鋒時機純靠距離常數 |

統帥（`bots/legion-commander.js`）其實已有三層指揮骨架與 18 個情境測試，輸在上面兩層太粗、沒有機動概念。二代架構沿用它的骨架，重寫戰場模型與計畫層。

## 三、BOT 架構規格（三層）

### 3.1 戰場模型層（每 10 tick 更新一次）

輸入：`obs`、歷史觀測、`data.map.features`。輸出：下面這些結構，供計畫層使用。

| 結構 | 內容 | 實作要點 |
| --- | --- | --- |
| 敵集群 `clusters` | 把可見與記憶中的敵團依距離（**12 格內，初值，P3 調**）聚成集群；每個集群有質心、總戰力、組成、朝向、速度向量、最後看見時間 | 朝向 ＝ 各團朝向的加權平均；移動中以速度向量為準 |
| 扇區 | 對每個集群算正面、側翼、背面三個扇區，角度依規格書 7.2 的側擊／背擊定義 | 給機動層判斷「我這團從哪個扇區接近」 |
| 威脅圖 `threat` | 地圖切成 **5×5 格的方格（初值，P3 調）**，每格算敵方火力覆蓋：弓兵射程（含高度修正）、近戰觸及＋速度×2 秒、槍林正面、盾牆正面 | 大河谷 48×30 ＝ 1440 格，每秒算一次遠在 50 ms 內 |
| 我方影響圖 `influence` | 同上，算己方 | 兩圖相減得「優勢圖」，用來選戰線與殺傷區 |
| 路徑 | 在威脅圖上做 A*，成本 ＝ 地形成本 ＋ 威脅權重；給機動層「低威脅路徑」 | 引擎的自動尋路只走最短路，繞側必須自己給路徑點 |
| 戰力估算 | 每團戰力 ＝ 點數 × 剩餘比例 × 相剋 × 地形 × 高度 × 狀態（槍林、盾牆、被纏住）；交換評估用蘭徹斯特平方律：集中火力的一方優勢 ∝ 兵力平方 | 回答「這裡打不打得贏」，取代現在的點數比 |
| 看不見的敵軍 | 總點數（公開）− 已確認殲滅 − 可見 ＝ 未知兵力；維持「未確認區域」清單（曾看過、多久沒看、是否在樹林） | 偵察機動的目標就是縮小未確認區域 |
| 地圖要點 | 從 `features` 算出渡口、門洞、高地、樹林、牆段的位置與「誰控制」 | 不依地圖名稱分支 |

### 3.2 機動計畫層（每 20 tick 更新一次）

| 元件 | 規格 |
| --- | --- |
| 角色 | 每團在任一時刻有一個角色：`scout` 偵察、`fix` 牽制、`flank` 側翼、`strike` 打擊、`escort` 護衛、`hold` 據守、`reserve` 預備、`capture` 佔旗、`siege` 攻城。角色由計畫層分配，單團層只執行角色 |
| 機動 | 第四章的機動庫。每個機動是狀態機：進入條件 → 階段（各有路徑點與完成條件）→ 放棄條件 → 收尾。一個機動同時指派多團，各團有角色 |
| 計畫選擇 | 每次更新，對每個候選機動算評估值 ＝ 預期戰力交換 ＋ 目標價值（旗、城門、時間）− 風險（未知兵力、路徑威脅）；選最高者。沿用統帥的姿態概念（集結、固守、迎擊、決戰、收攏、進攻、搜敵）當作大狀態，機動掛在姿態之下 |
| 時序 | 機動階段有「等待條件」：例如側翼組到達指定扇區才允許牽制組接戰；**30 秒重評估**（使用者意見，已採納）：到時重算機動價值，有進展且進入條件仍成立就續 30 秒；放棄只看「無進展」（30 秒內離目標點沒變近）或「進入條件不成立」，不看時間 |
| 任務式指揮 | 計畫層只給單團「目標、路徑點、角色、放棄條件」，不下單步指令；單團層自己處理走位、架槍、後退 |
| 可解釋 | 每條指令的 `intent` 寫「機動名／角色／階段」，回放可核對 BOT 在執行什麼 |

### 3.3 單團執行層（每次決策）

沿用現有規則庫（槍林、盾牆、弓兵後撤與集火、切入、衝鋒方向、隘口縮窄），只改成「依角色與計畫層給的目標執行」，而不是「各自找最近敵人」。單團層仍保留自保反射：被騎兵逼近的弓兵後退、側翼來騎兵的長槍轉向，這些不用等計畫層。

### 3.4 單檔內的模組切分

單檔 ES2020 仍可切成閉包模組：`model/`（集群、威脅圖、路徑、戰力）、`plan/`（機動狀態機、評估）、`exec/`（兵種動作）、`modes/`（攻城攻、攻城守、佔點）。用建置腳本把多檔合成單檔（`scripts/build-legion-bots.ts` 已有這個做法）。每個模組可被情境測試單獨驅動。

### 3.5 效能

戰場模型每秒一次、計畫每兩秒一次、單團每次決策（0.5 秒）一次。目前最長決策 2 ms，上限 50 ms；威脅圖與 A* 放在每秒那一層，預估 5～10 ms，仍有餘裕。超過 **20 ms（初值，P3 調）** 就要降解析度。

## 四、機動庫（第一版 11 個）

每個機動四欄：**定義**（教範）、**進入／放棄**、**實作要點**（遊戲 AI）、**驗收情境**（第五章編號）。「待補」是使用者可填的經驗。

### M1 偵察 Recon

- **定義**：以快速單位先取得視野，縮小未確認區域，確認路線安全後主力才動。教範：偵察牽引（recon pull），主力跟著偵察結果走，不是照計畫走。
- **進入**：開局；或未確認區域面積超過門檻；或交戰中斷 **30 秒**。**放棄**：偵察單位損失超過 **30%（待審）**，或所有關鍵區域（渡口、樹林、高地、門洞）已確認。
- **實作**：輕步兵為主要偵察單位（便宜、快、可犧牲），輕騎兵只在對方無輕騎時用來搶先卡位；目標 ＝ 未確認區域中「價值最高、路徑威脅最低」者；到達視野邊緣即停，不進入威脅格；發現敵集群後回報並退出射程。重騎兵開局即可當「硬偵察」探另一側渡口（見使用者答）。
- **驗收**：S13、S19、S20。
- **使用者答（T1，大河谷）**：
  - 偏好編隊（500 點）：**槍 2、劍 5、輕步 1、重騎 2**（495，較偏好）；或槍 1、劍 3、盾 1、弓 2、輕步 1、重騎 2（499）。
  - 不帶弓是**地圖判斷**，不是針對對手：大河谷除淺灘外沒有好的弓兵輸出點，弓兵太好殺、要人顧又沒輸出。所以配兵是「地圖 × 角色」的函數，由訓練搜尋；此編隊是大河谷佔點的種子之一。
  - 派誰：輕步 CP 值遠高於輕騎，三隊輕步的可操作性勝過一隊輕騎；兩者都有技能可脫離。
  - 走哪：重騎 2 組與輕步 1 組**各探一邊的橋**；劍士分 2～3 團走其中一邊，到橋邊**不過橋**等偵察結果；其餘部隊走中間。
  - 過河條件：橋對面確認沒有威脅（特別是騎兵）→ 橋邊劍士過橋。前哨繼續探對方布置、兼吸引注意。
  - 中間的處置：對方少量壓上 → 局部應戰、等前哨消息；對方大量壓上 → 拖延到過河的劍士與重騎就位，並把對方**控制在淺灘以外**（淺灘太窄，架槍兵不好應對）。
  - 不過河條件：對側有騎兵，或重騎那一側有槍兵 → 拉回樹林，繼續觀察對方是否過河。
  - 對 M1 的修正：偵察與繞側是同一個開局動作，不是先偵察再決定；「過河」的決策單位是橋邊那 2～3 團劍士，不是全軍。

### M2 牽制固定 Fix

- **定義**：以一部兵力黏住敵軍正面，讓它不能轉向、不能脫離，為側翼創造條件。教範：fix and flank；錘砧的「砧」。
- **進入**：已決定側翼機動且側翼組出發。**放棄**：牽制組戰力低於 **50%（待審）**且側翼尚未到位；或敵軍已轉向側翼組。
- **實作**：牽制組 ＝ 劍士為主，長槍面對敵騎兵方向架槍；盾兵只在敵方弓兵多時放前排擋箭；在敵正面扇區射程邊緣接戰；弓兵在牽制組後方射擊被纏住的敵團（S3）；**不追擊**，敵退就停在原地維持威脅。
- **驗收**：S2、S18、S21。
- **使用者答（T2）**：七兵種定位與數值問題見 1.7。對牽制的含意：劍士是萬用主力，適合放前面；長槍放在敵騎兵來向；盾兵沒傷害，只有對面大量弓兵時才值得放前排；弓兵要有近戰掩護或高地才有輸出，不當牽制。

### M3 側翼行軍 Flank March

- **定義**：從敵軍側翼或背面扇區接近，路徑避開敵火力覆蓋與視線。教範：坎尼雙翼、蒙古側翼迂迴。
- **進入**：敵集群已定位、有牽制組、存在一條威脅低於門檻的路徑到側翼／背面扇區；**重騎例外：開局即出發**（使用者答 T3），不等敵集群定位。**放棄**：路徑上發現未知敵軍、側翼組被發現且敵軍轉向（改為 M6 脫離，或留在側翼當牽制威懾——被看到仍有價值）、逾時。
- **實作**：側翼組 ＝ 騎兵或劍士＋輕步；路徑由威脅圖 A* 產生，偏好樹林（隱蔽）與視線死角（高度遮蔽）；分階段：出發 → 迂迴點 → 待機點（敵背面扇區外 **8 格，待審**）→ 回報到位。到位後等 M4 的衝鋒窗口。
- **驗收**：S18、S22、S23。

### M4 錘砧衝鋒窗口 Hammer

- **定義**：側翼組在敵軍被牽制、側背暴露、路徑無槍林時發動衝鋒，衝完立刻脫離。教範：錘砧的「錘」；騎兵循環衝鋒。
- **進入**：M3 到位且 M2 持續中；目標團被纏住、或朝向與我接近方向夾角超過 120°、**或目標同時受兩個方向（夾角 > 90°）威脅**；衝鋒路徑上無**已架好**的槍林（引擎：槍林架設 30 tick、收槍 20 tick、只有 `braceFacing` 正面減免 50%，圓陣減半——所以「正在架」與「架錯方向」都算窗口）、無淺灘樹林；冷卻就緒。**放棄**：目標轉向正對、槍林出現在路徑上、敵騎兵來堵、**衝鋒距離不夠且無法拉近（寧可不衝）**。
- **實作**：優先目標依序：弓兵、被纏住的步兵、正在轉向的團；衝鋒方向用 `target`；衝完自動轉 M6 脫離，重整後若窗口仍在則再衝。劍士的突擊同理，但只對側背。
- **驗收**：S2、S16、S18、S24。
- **使用者答（T3）**：
  - 出發：**開場就繞**。對方開局不一定知道我方配置，避開視野繞到敵後威脅最大；被看到也是威懾與牽制，對方至少得調槍兵防守，正面就有機會。多方向都有騎兵時對方易顧此失彼。本遊戲沒有能正面突破槍林的單位，所以騎兵不走正面。
  - 路線：盡量避開對方可能的視線。
  - 衝的時機：先定這隊騎兵的目的——關鍵一擊，還是替前線製造機會；核心是**出其不意**，用速度讓對方來不及反應。收割殘兵前先確認附近沒有可能埋伏的敵兵力。
  - 不衝：槍兵轉向、敵騎來堵、距離不夠。衝到最大距離所需時間多數兵種都能拉開，所以要其他兵團配合拖住。進階：一隊衝鋒逼對方迴避，另一隊瞄準迴避路徑打時間差（難度高，第二版再做）。
  - 衝完：兵力有餘裕且殘敵偏多、又是劍／槍／重騎時 → **拉開**，交給步兵收尾或等二次衝鋒；只有關鍵時刻才留下混戰。追殺只對殘兵、弓兵、輕步。
  - 對 M4 的修正：優先目標改為「能一擊打穿的」（弓兵、輕步、殘團）優先於「被纏住的步兵」；拉開是預設，混戰是例外。
  - 使用者對「BOT 反應快」的回應（已採納）：問題不是對方反應不過來，是反應了也沒用——拉開要時間，騎兵可能先到，或其他兵團從另一方向限制，對方要麼被騎兵衝、要麼被劍士衝。引擎印證：槍林 3 秒才架好且只有正面，兩方向同時威脅就是衝鋒窗口。

### M5 佯退誘敵 Feigned Retreat

- **定義**：以誘餌組邊退邊保持接觸，把敵軍引入我方殺傷區（弓兵射程內、槍林正面、高地下方），敵軍越線後主力接戰。教範：蒙古佯退、帕提亞射法。
- **進入**：敵軍有追擊傾向（過去 **10 秒**內朝我前進且脫離其集群）；我方殺傷區已架好（M8）。**放棄**：誘餌組被纏住（切入脫離）、敵軍不追。
- **實作**：誘餌 ＝ 輕步或輕騎；維持與追兵距離 **4～6 格（待審）**，速度壓到讓敵人覺得追得上；殺傷區由弓兵、長槍、盾兵組成，弓兵不射誘餌附近的敵人直到越線；越線訊號 ＝ 敵團中心進入殺傷區多邊形。
- **驗收**：S16、S25。
- **使用者答（T4）**：被誘過（戰意）：追擊殘兵或武將時衝進窄口、轉角，被藏在角落的騎兵或盾槍陰。追不追沒有單一規則，是四項綜合：**我方兵力狀況、對方撤退方向（是否進窄口、樹林、未確認區）、目標是否高價值、追擊後我方戰線是否拉長給對方可乘之機**。實作上寫成追擊前檢查：撤退方向經過未確認窄口或轉角 → 先派輕步探，主力不追。

### M6 脫離重整 Disengage & Regroup

- **定義**：接戰不利或任務完成時有序撤出，到集結點恢復隊形與技能冷卻，再決定下一步。教範：交替掩護撤退。
- **進入**：衝鋒結束；局部戰力交換低於 **0.7（待審）**；計畫層姿態轉「收攏」。**放棄**：被纏住無法脫離（轉為死守或切入）。
- **實作**：撤退方向 ＝ 威脅圖最低且朝向友軍的方向，不是「反方向」（避免退進另一支敵軍的攔截路線）；掩護組（盾兵、長槍）面向敵軍後退；弓兵先走；集結點在我方影響圖高處。
- **驗收**：S26、S27。

### M7 護衛 Escort

- **定義**：保護弓兵與側翼免受騎兵與輕步突襲。教範：預備隊就近反應。
- **進入**：常駐；有威脅（會動且朝弓兵來的敵團）在 **15 格（待審）**內。**放棄**：威脅消失。
- **實作**：長槍面向騎兵來向提前架槍（S4、S8、S15）；劍士攔截輕步；盾兵掩護區對準箭矢來向；弓兵與護衛的相對位置由計畫層給（弓兵在護衛後方 2.6 格）；不被佯攻騙：一團長槍只對最高威脅方向，其餘方向靠弓兵後撤。
- **驗收**：S4、S6、S7、S8、S15。

### M8 殺傷區據守 Kill Zone / Hold

- **定義**：選一個地形有利的位置架好，讓敵人上來打。教範：防禦陣地選擇（高地、渡口、隘口）。
- **進入**：姿態固守或迎擊；守城時常駐。**放棄**：敵軍繞過不來、時間或分數壓力要求進攻。
- **實作**：位置由優勢圖選：高地給弓兵、渡口或門洞正面給長槍盾兵、兩翼靠不可通行地形；預備隊在後方；弓兵集火規則（S3、S12、S17）。
- **驗收**：S12、S17、S28。
- **使用者答（T6）**：大河谷沒有「站了就贏一半」的位置——目前 BOT 太弱，根本不需要搶戰略點，無參考價值。新圖第一眼看三件事：**平地狀況（適不適合跑馬）、窄口、必經點附近的高地**。城池圖與平原圖的關鍵位置**等引擎 0.4 出圖後再填**（T6 餘項）。

### M9 攻城 Escalade & Gate Assault

- **定義**：多點同時施壓迫使守方分兵，主攻一點登城或破門，登城後沿牆頂清梯口、開門引主力。教範：多點佯攻、集中突破。
- **進入**：攻城戰攻方；偵察完成（M1）確認守方牆段兵力分布。**放棄**：主攻點損失超過 **40%（待審）**時改換突破點。
- **實作**：階段：接近（樹林集結、盾兵舉盾前推吸箭）→ 佯攻兩點架梯 → 主攻點架梯或**護衛衝車到門**（守方最薄弱牆段由威脅圖找）→ 砲擊 3 發用在牆頂弓兵或門洞外的守方集結（打不到門洞內側）→ 登城組（劍士、輕步）上牆守住梯口、往門樓推 → 破門後攻 A 旗 → 推 B。騎兵在城外清守方出擊部隊、護衝車，不進城。多路線（側門、缺口）用來分散守方。
- **驗收**：S29、S30、S31。

### M10 守城 Wall Defense & Sally

- **定義**：弓兵在牆頂射擊，步兵守梯口與門洞，預備隊依攻方主攻點機動，必要時出擊打攻方弓兵或雲梯隊。教範：內線機動。
- **進入**：攻城戰守方常駐。**放棄**：A 失守後退守 B，牆頂部隊下牆。
- **實作**：牆段分配 ＝ 依攻方兵力分布每 2 秒重算；雲梯架好、梯口 1 格內無敵就推倒；門洞內側槍林對門（砲擊陰影區）；預備隊在本陣與牆之間；出擊條件 ＝ 攻方弓兵無護衛且在門洞 **10 格（待審）**內，或衝車操作兵護衛薄弱（開正門出擊、得手即退回關門，風險自控）；砲擊落點標記出現時牆頂部隊散開。
- **驗收**：S32、S33、S34。

### M11 佔點輪轉 Capture Rotation

- **定義**：三旗分配兵力、得分競賽的進退、後備輪換。沿用現有佔點元件（v1.100 核心），改成由計畫層分配角色。
- **進入**：佔點模式常駐。
- **實作**：開局取**近旗＋中旗**，遠旗放棄；重點兵力給中旗（分數高，兵力分散會搶不贏）；得分落後且兵力明顯佔優時才攻第三旗，「有優勢但不大」就守好兩旗；守旗用**劍士＋長槍架槍林**對付輕步，騎兵截擊為輔；團戰力低於 **50%** 即換後備。
- **驗收**：S10、S11、S35。
- **使用者答（T5）**：選二旗＝近旗＋中旗，重點兵力給中旗（引擎印證：中旗每秒 2 分、側旗 1 分）。就算分數相同，中旗仍是戰略點，可作進攻另一側的中轉站。使用者另指出**大河谷的兩側旗離中旗太近，取捨意義不大**（待討論）→ 列入 P1 地圖設計：新平原圖把側旗拉遠、讓「守兩旗還是搶三旗」成為真選擇。放棄遠旗的時機：開局，以及有優勢但不大時——浪費兵力去攻對方很可能重兵的地方，不如守好已佔的。反輕步洪流：劍士＋槍兵、或純劍士對拚都能贏輕步，槍林架起來守點很輕鬆，不覺得輕步難打（騎兵沒試過）。後備輪換：戰力損失達一半就換。

### 不做的

- 不做逐秒座標劇本；所有機動只用可觀測條件。
- 不依對手代號、種子、評測時間切換策略。

## 六、訓練流程

### 6.1 第一步：工程（LLM 寫，不計時）

產出：三層架構、機動庫 M1～M11、情境 S1～S37 全過、兩模式三張圖合法運作。

分工建議（沿用 phase4 雙線）：

| 線 | 負責 | 版號 |
| --- | --- | --- |
| 主線（Codex） | 戰場模型層、計畫層骨架、M6～M8、M10、M11、共同評測工具 | 奇數 |
| 進攻線（Sonnet） | M1～M5、M9；攻方候選 | 偶數 |
| 整合 | 主線整合、每次整合重跑情境與矩陣 | 奇數 |

規則：先過情境再看勝率；一個機動一個凍結交付；不得為了勝率把機動退化成「找最近敵人」。

### 6.2 第二步：參數訓練（真正的訓練）

工程完成後，BOT 的行為由兩類東西決定：**機動參數**（本文件所有「待審」數字與各機動門檻，預估 60～100 個）與**計畫選擇策略**（評估函數的權重）。這兩類用搜尋法調：

| 項目 | 規格 |
| --- | --- |
| 方法 | 演化策略（CMA-ES 或簡單 (μ, λ) 演化）；每代 **20 個候選（已定）**，每候選對固定對手集打 **40 場（已定）**（20 種子 × 雙座位） |
| 對手集 | 歷代基準（v1.114、v1.159 的佔點元件）、現有陪練三隻、**形狀化對手 8 隻（新寫，見 6.4）**、自我對戰（上一代最佳） |
| 目標函數 | **勝率 80% ＋ 戰力交換 20%（已定）**。淘汰條件：任何情境測試失敗，或衝鋒撞槍林正面 > 5%。行為指標**不當門檻、只記錄**（使用者：門檻會強迫繞側，是另一種限制策略；「會不會」由情境測試守，「要不要用」由勝率決定） |
| 種子 | 探索集（1～49999）與驗證集（50000～99999）分開；驗證集不參與選擇 |
| 退步界線 | 對任一歷代基準或任一形狀化對手勝率下降超過 **10 點（已定）** ＝ 不接受（40 場的隨機誤差約 ±8 點，5 會誤判、15 等於沒管） |
| 算力 | 一場約 1～3 秒、單 worker；每代約 20×40×2 ＝ 1600 場 ≈ 1 小時；先跑 **10 代（已定）** |
| 可重現 | 每代存參數向量、種子、rngBase、結果；最佳候選凍結為版本 |

### 6.3 第三步：循環

最佳候選入訓練池 → 新寫一隻針對它的形狀化對手（例如專門繞背它的弓兵）→ 回到 6.2。每輪結束用驗證集與保留池重測。三輪後再評估要不要擴機動庫。

### 6.4 形狀化對手（exercise opponents）

不必強，但要有明確形狀，逼 BOT 的各機動被用到：

| 對手 | 形狀 |
| --- | --- |
| 正面壓 | 全軍直線推進（現有陪練） |
| 雙翼包 | 兩組從兩側繞、中央弱 |
| 騎兵繞背 | 四團輕騎專打弓兵 |
| 誘退者 | 輕步前出後退，主力在後架槍 |
| 分路搶旗 | 佔點：輕步洪流三路 |
| 龜陣 | 盾弓固守高地（v1.114 殲滅元件改寫成佔點／守城） |
| 林中伏兵 | 主力藏樹林等過河 |
| 巷弄伏兵（新增，待審） | 城池：騎兵與盾槍藏在巷口轉角，專打進窄口的部隊與追擊組 |
| 城牆弓手 | 守城：全弓上牆、門洞槍林 |

### 6.5 行為指標（只記錄，不當門檻）

全部畫在訓練報告上給人看；唯一例外是「衝鋒撞槍林」當淘汰條件（那是錯誤，不是風格）。「側背擊殺比」作廢：混戰中朝向每秒在變，對方自己轉身也會產生側背擊殺，量不準。

| 指標 | 定義 | 用途 |
| --- | --- | --- |
| 衝鋒側背比 | 每次衝刺引擎記錄的接觸方位 `flank`，非正面的衝刺 ÷ 全部衝刺 | 只看接觸那一刻，引擎已有欄位 |
| 夾擊率 | 敵團崩潰（潰逃或減員過半）那一刻，我方是否從兩個夾角 > 90° 的方向同時接戰；被夾擊的敵團 ÷ 崩潰的敵團 | 量幾何，不量朝向；錘砧有沒有成形 |
| 偵察覆蓋 | 主力接戰前已確認的關鍵區域比例 | M1 |
| 到位時差 | 側翼組到位與牽制組接戰的時間差（絕對值） | M2／M3 協同 |
| 衝鋒撞槍林 | 衝鋒中撞上已架好槍林正面的比例（**> 5% 淘汰**）；每次衝鋒擊殺 | M4 |
| 弓兵存活輸出 | 弓兵可持續射擊的 tick 數；被貼身前的損失 | M7 |
| 撤退損失 | 脫離機動期間的損失比例 | M6 |
| 攻城效率 | 架梯成功率、梯被推倒比例、衝車抵門秒數、A 佔下時間 | M9 |
| 守城反應 | 攻方集中後守方預備隊到達秒數 | M10 |

這些從回放事件算，不需要引擎改動（`impact`、`destroyed`、`enter`、指令 `intent` 已足夠；攻城新增 `ladder`、`gate` 事件）。
