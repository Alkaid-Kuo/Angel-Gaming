# M2 小規模軍備競賽試跑報告

Oct 22, 2026 · 參賽包：引擎 0.2.0／規格書 v0.3 · 評測使用同一份參賽包（正式模式）

依「軍備競賽執行手冊」試跑 2 家 AI × 2 種風格（速攻、快速擴張），每次 90 分鐘。第一家是 Claude Opus。第二家先用本機 Qwen，在 90 分鐘內無法完成，依你的指示退回方案一，改由 Claude Sonnet 擔任。

## 一、結論：M2 過關

| 條件 | 結果 |
| --- | --- |
| 對基準 Bot 勝率 ≥ 70% | **達成**：四隻作品對基準 Bot 正式模式 100 場都是 100%，4 人局（對 3 隻基準 Bot）平均名次都是 1.0 |
| 風格可區分 | **達成**：快速擴張的首次擴張早（282～1013 tick）、採集量高（約 6000）、會蓋塔；速攻不擴張或晚擴張、全長槍兵、比賽早結束。速攻的首次傷害只有 Sonnet 接近手冊目標（1523 對目標 < 1500），見第五節 |
| 規則文件未被誤讀 | **達成**：四隻作品都正確使用 API（抽查各 10 場，被拒的指令為 0）；選手回報的疑點都是「沒寫清楚」或「容易漏看」，沒有寫錯的地方，已補進規格書 v0.4 |
| 無嚴重漏洞被利用 | **達成**：沒有作品利用漏洞。但兩隻快速擴張都獨立指出「防禦塔全額計入資產分數」會讓龜縮蓋塔成為主流解（Sonnet 的作品在僵局中最多蓋到 48 座塔），屬於平衡問題，**需要你決定** |

需要注意：方案一的兩家都是 Claude（Opus 與 Sonnet），同一廠商。結果顯示兩個模型的作品差異很大（見第三節），作為試跑足以驗證流程，但 M5 正式比賽仍需要不同廠商。

### Qwen 的經過與結論

試了 4 次速攻，判定「在 90 分鐘內無法完成」，所以快速擴張沒有用 Qwen 跑。

| 次 | 時間 | 結果 | 原因 |
| --- | --- | --- | --- |
| 1 | 03:55～04:49 | 沒有任何輸出 | opencode 在 Windows 非互動執行時沿用上層資料夾、並等待標準輸入，卡住 |

| --- | --- |
| 05:41～05:42 | 讀 spec.md、baseline.js、template.js、README |

- 90 分鐘內一場對戰都沒跑過；沒有版本快照、final.js、NOTES.md，CHANGELOG 與 BUGS 都是空的。
- 生成速度從每秒約 12 token 降到約 5 token（上下文累積到約 45k token），90 分鐘總共只生成約 3 萬 token，大部分是思考內容。
- 事後測 `my-bot.js`：可以載入、沒有例外，但整場只生產工人（9 名），沒有任何戰鬥單位。對基準 Bot 正式模式 20 場全敗。
- **結論**：本機 27B（Q3 量化、16 GB 顯示卡）的速度不足以參加限時軍備競賽，這不是規則文件的問題。結束後已關閉 llama-server 釋放顯存。

## 四、規則回饋（彙整 4 份 BUGS.md）

| Expander | 整數旋鈕給小數時，錯誤訊息說「超出範圍」 | **已修正（M3）** |
| SpeedRush、Blitz | 統計欄位（首次造成傷害等）沒有定義；`stats.multipliers` 有 null | **已補**：規格書 v0.4「對局統計」一節 |

| Blitz | `minerals` 不扣除已下令未開工的建築 | v0.4 寫明；**可選**：觀察資料加「預訂礦量」欄 |

| SpeedRush | 工人中心到礦點邊緣 ≤ 200 才能開採，又說中心不可進入礦點 | 規格已寫「只檢查中心點」，不衝突 |
| Blitz | `attack` 目標必須看得到，執行期間不回擊 | v0.4 寫明 |

| QuickExpand | 極端早攻旋鈕的基準 Bot 會讓快速擴張掉約 10% 勝率 | 風格取捨，不處理 |

## 五、對手冊與評測方法的建議

1. **速攻的統計目標**：「首次造成傷害 < 1500」偏嚴，只有 3 隻兵就出發的 Blitz 接近（1523）。建議改為相對值，例如「首次造成傷害比對手早」或「六成以上勝場在 tick 3000 前以淘汰結束」。
2. **基準 Bot 太弱**：四隻作品幾乎從第 1～3 版就全勝，70% 的最低標準篩不出差異。建議 M5 前把基準 Bot 的預設旋鈕改成較強的組合（M2 已觀察到攻擊門檻 30 對預設值 4 戰全勝），或另加一隻「進階基準 Bot」。
3. **版本線**：加測「對前一版」與「對 v1」的勝率。
4. **AI 執行環境要對等**：本機 27B 的速度不足；M5 正式比賽建議全部用雲端 API。
5. **執行器的看門狗**：opencode 非互動執行卡住過兩次、被輸出上限截斷一次。M5 的執行器需要「N 分鐘無輸出即告警」與「單次輸出被截斷即告警」。本次已修正 `scripts/run-opencode-trial.ts`：關閉標準輸入、以 `--dir` 與 `PWD` 指定工作資料夾、隔離 opencode 資料目錄、記錄運行日誌。
