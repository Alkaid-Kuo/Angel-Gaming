# CS 射擊 試玩頁 Bot 等級任務書

## 背景

專案 Angel Gaming（電競戰隊經營遊戲）的第二個電競項目「攻防戰」：參照 CS 的 5v5 攻防射擊，2D 俯視，確定性整數引擎 30 TPS。2026-10-31 已經 PR #2 合進 `main`（b938fd5）。規格書 `docs/2026-10-29_CS射擊項目計畫與規格.md`（v1.0），項目總覽 `docs/2026-10-29_CS射擊_夜間進度報告.md`。凍結規則：選手 API 1.0 與引擎 1.0.0 凍結，**不改** `src/shooter/sim.ts`、`config.ts`、`api.ts`、`map.ts`、`bots/`（含 `bots/shooter-src/`、`bots/shooter-baseline.js`、`bots/shooter-practice.js`）；`src/shooter/runner.ts` 只能加不改預設行為的驅動層選項。現況：試玩頁 `web/shooter.html`（程式 `src/web/shooter/`：main.ts、worker.ts、protocol.ts、render.ts、hud.ts）裡人類之外的 9 個位置、以及「觀戰模式」的 10 個位置，全部固定用陪練 Bot v5（`shooter-practice.js`，16 KB 的對照組，沒有指揮與輪轉）。基準 Bot 2.1（`shooter-baseline.js`，179 KB，四層架構、隊內靠 `say` 協調）只在經營層觀戰（`#watch`）時由 `worker.ts` 的 `watch` 路徑載入，走 `src/shooter/gateway.ts` 的 `gatewayDriverOptions(request, bot)`。選手衍生在 `src/shooter/players.ts`：`ShooterRole = entry|awp|support|anchor|lurk`、`ShooterPlayerSpec {role, version 1～5, habit}`、`derivePlayer`、`reactionTicksFor`、`BALANCED_ROLES`、`ROLE_KNOB`；閘道把衍生結果變成 `ShooterRunOptions.attributes` 與 knobs、每個座位 `reactionTicks`，人類座位不延遲。基準 Bot 對陪練 v5 整場勝率 97.5%～100%；版本 1～5 的強度差只靠 aim／reaction／awareness／discipline 四個旋鈕。使用者（郭子洋／Alkaid，Unity 工程師）的規範：一律繁體中文；回覆簡潔；不直接 commit 到 main；任何覆蓋或刪除操作執行前必須先問（在工作階段裡就是先在回報說明、不要自行刪檔）；不 push。視野公平是底線：引擎層強制，不准給 Bot 視野外資訊。確定性：同種子同操作結果相同，不用 `Math.random`／`Date` 影響結果。lint 用 `npx eslint src bots test scripts/build-shooter-bots.ts scripts/shooter-*.ts scripts/manage-*.ts`（`npm run lint` 可能被使用者主目錄 checkout 的未版控草稿卡住，工作樹裡沒有那些檔案，可先試 `npm run lint`）。既有已知失敗：`test/legion-ai.test.ts` S16 是軍團戰舊問題，不要修。瀏覽器預覽用 `.claude/launch.json` 的 `web`（vite 5173，被占時會改埠），網址是 `/web/shooter.html`。

## 任務

讓攻防戰試玩頁 `web/shooter.html` 的玩家能體驗到所有等級的 Bot——隊友與對手各自可選「陪練 v5」或「基準 Bot 版本 1～5」，觀戰模式同樣可選兩隊各自的等級。先把本任務書全文存成 `docs/2026-10-31_CS射擊_試玩頁Bot等級任務書.md` 並 commit，再開工。

## 設計

1. **設定卡**（`web/shooter.html`＋`src/web/shooter/main.ts`）：新增兩個下拉「我方隊友」「對手」，選項：陪練 v5、基準 v1、基準 v2、基準 v3、基準 v4、基準 v5。預設都是「陪練 v5」，維持現在的行為。觀戰模式時兩個下拉就是「T 側（0～4）」「CT 側（5～9）」。每個下拉旁一行小字說明這一級大概多強（陪練：對照組、會買槍打包但沒有指揮；基準 v1：反應最慢；基準 v5：反應最快，經營層的頂級選手）。
2. **訊息協定**（`src/web/shooter/protocol.ts`）：`start` 訊息加 `lineup: { team: BotLevel; enemy: BotLevel }`，`BotLevel = { kind: 'practice' } | { kind: 'baseline'; version: 1|2|3|4|5 }`。沒帶就是兩邊陪練。
3. **Worker**（`src/web/shooter/worker.ts`）：基準 Bot 的座位用 **經營層同一條路徑** 建控制器與屬性：角色照 `BALANCED_ROLES` 排 5 人（人類座位佔掉的那個角色就空著不衍生），`habit` 由比賽種子與座位號雜湊出來（用 `src/shared/prng` 或既有雜湊，不要 `Math.random`），`derivePlayer` 算屬性、`reactionTicksFor` 算延遲，knobs 照 `ROLE_KNOB`。**不要在 worker 裡複製 `gateway.ts` 的座位邏輯**：把 `gateway.ts` 裡「一份 `PlayerSpec` → 屬性、knobs、reactionTicks」那段抽成可共用的純函式（例如 `seatOf` 已有就直接匯出並使用），試玩與閘道都呼叫它。陪練座位維持現狀（不吃屬性）。人類座位一樣不延遲。基準 Bot 第一次用到時才在 Worker 裡編譯（`watch` 路徑已經這麼做），設定卡按開始後顯示「載入基準 Bot…」避免看起來卡住。
4. **同一條路徑的證明**：寫一個測試——觀戰模式選「基準 v3 對 基準 v3」、固定種子，Worker 用的 `ShooterRunOptions`（不含 record）與閘道 `gatewayDriverOptions` 對一張等價請求單（10 個 `PlayerSpec` 同角色、同版本、同 habit）建出的選項逐欄相同；若兩邊能跑完同一場且 `finalHash` 相同就一併驗證，不能的話在報告說明差在哪（例如賽制參數）。
5. **文案**：試玩頁現在寫「隊友與對手固定為陪練 Bot v4」，實際是 v5——改成跟著選項顯示。`web/index.html` 攻防戰入口那段提到「9 隻陪練 Bot」也改成「可選陪練或基準 Bot」。
6. 回放：下載的回放與 `shooter replay` CLI 要仍能核對（回放裡若有記 Bot 名稱／版本，把等級帶進去；沒有就不用加欄位）。

## 不做

- 不改 `src/shooter/sim.ts`、`config.ts`、`api.ts`、`map.ts`、`bots/`。不新增地圖。
- 不動經營層（`src/manage/`、`src/web/game/`、`src/web/manage/`）；閘道 `gateway.ts` 只能做「抽函式匯出」這種不改行為的重構，`runGatewayMatch` 的結果雜湊必須和改前相同（既有測試會抓）。
