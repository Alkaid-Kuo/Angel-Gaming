偵測定義（每兵每條件只記第一次）：
- ILLEGAL：所在格該層不可站（`walkAt` 為 false，爬梯中不算）連續 ≥ 3 秒
- LAYER：層與團不同、沒欠換層（`owe<0`）、沒在爬梯，連續 ≥ 5 秒
- FAR：離團中心 > 團半徑 + 3 格（`FARD=3`）、10 秒內位移 < 1 格、3 格內沒有敵兵，連續成立（排除近戰纏鬥）

## 2. 根因分類、重現點、程式位置

共同根因（C1、C2、C3，佔 106/116 人 ≈ 91%）：**士兵移動完全沒有尋路**，只有「直線走向隊形點 → 被擋就換成直線走向團中心 → `slide` 沿單軸滑」。
`src/legion/sim.ts:2504-2505`：
```
if (!offLayer && gx === s.sx && gy === s.sy && (tick+s.k)%10===0) s.blocked = !clearLine(...)
if (!offLayer && s.blocked && gx === s.sx && gy === s.sy) [gx,gy] = snapPoint(map, r.x, r.y, ...)   // ← 只是團中心本身
```
`snapPoint(團中心)` 還是直線。目標在牆／建築另一側時：目標方向正對牆 → 單軸 slide 無處可滑 → 永久不動；目標方向略偏 → 沿牆以「分量×速度」爬行（seed 185 盾兵 7 秒爬 1 格）。團中心用 `findPath`（`moveTo`，sim.ts:2224），士兵沒有。`lag > 2000` 只會讓團放慢速度（sim.ts:2263），不會等人。

### 對決定性（hash）、既有測試、凍結 BOT 的影響
- **hash／replay**：凡是在攻城地圖上觸發到這些分支的對局，軌跡都會改變 → 這類對局的 hash、勝負、長度全變；舊的 0.4 replay 會 desync。若採 F1′，新欄位要進 `Hasher`（sim.ts:3346 附近 owe 那段）。需決定是否升 `LEGION_ENGINE_VERSION`／替舊 replay 標註。
- **0.3.2 地圖零變動**：`test/legion-layer.test.ts:296`（大河谷 push vs ambush seed 42，hash `a7be4b4131586b98`、3042 tick）。**F1 若不加 `pathEnv !== null` 閘門，hash 變成 `3643c7684886384e`（測試失敗）**——因為一般地圖也會走「直線被擋」分支。加閘門後（用 `pathEnv` 當條件）：legion-layer.test.ts 14/14 通過；F2/F3/F4 單獨套用也不影響（它們只碰樓梯）。
- **既有測試**（在 `dist/exp` 複本跑 `vitest run test/legion`，117 項）：F1~F4 全套後只有 `test/legion-siege-bot.test.ts:80-81` 的「攻城陪練對攻城陪練」失敗——**seed 3 守方不再開始推雲梯（`toppling` 全程 false，3004→2825 tick 結束）**；seed 7 仍會推（3028 tick）。這是測試鎖定特定軌跡（`expect(toppling).toBe(true)`），不是功能壞掉，可改測試種子或放寬為「任一種子推過」。其餘全過；`S16 佯攻誘敵`（legion-ai.test.ts）在未修的複本上也失敗，與本修法無關（複本環境差異，未深究）。
- **凍結 BOT**：`bots/` 一個字沒動。0.3.2 的凍結 BOT（commander／marshal 等）只在無 `pathEnv` 的地圖跑 → 不受影響。攻城陪練 `bots/legion-src/siege.js` 的「空殼偵測」（line 41、394 附近）修後幾乎不會觸發，但留著無害。
- **勝率**：攻城陪練 vs 攻城陪練，baseline 攻方 262 勝／守方 38 勝；修後 275／21（卡住的盾兵回得了隊，攻方更強）。平均 3162 → 3014 tick。若要保持雙方平衡需重新調陪練。
- 效能：卡住的士兵每 10 tick 一次 A*（共用 scratch）；原型 300 場沒有可見變慢（每場約 1.5～2 秒）。
