## 三、兩線共用的介面契約（貼在兩邊；改動要兩線都簽）

### 3.1 目錄
```
bots/legion-src/b2/
  index.js            入口：declare、deploy、decide（主線）
  COOPERATION.md      版號、交付、檢查點、參數表、介面改動紀錄
  model/              戰場模型層（主線）
    clusters.js       敵集群、扇區
    threat.js         威脅圖、影響圖、優勢圖
    path.js           威脅圖 A*
    strength.js       戰力估算、交換評估
    unknown.js        未確認區域
    terrain.js        地圖要點（從 features 算）
  plan/               計畫層
    roles.js          角色常數與分配（主線）
    maneuver.js       機動狀態機骨架、30 秒重評估（主線）
    select.js         計畫選擇、姿態（主線）
    maneuvers/        每個機動一檔：m1-recon.js … m11-capture.js（M1～M5、M9 進攻線；其餘主線）
  exec/               單團執行層（主線；進攻線可提案）
  modes/              siege-attack.js（進攻線）、siege-defend.js、capture.js（主線）
bots/legion-src/b2-exercise/   形狀化對手（各寫各的）
```

### 3.2 模型層給計畫層的結構（主線定義，進攻線只讀）
- `model.clusters[]`：`{ id, cx, cy, strength, kinds, facing, vx, vy, lastSeen, sectors: { front, side, rear } }`，扇區用規格書 7.2 的側擊／背擊角度。
- `model.threat.at(x, y)`、`model.influence.at(x, y)`、`model.advantage.at(x, y)`：5×5 格方格，單位座標查詢。
- `model.path(from, to, opts)`：威脅圖 A*，回傳路徑點陣列（單位座標）；`opts.layer`、`opts.cavalry`、`opts.threatWeight`。
- `model.strength(reg)`、`model.exchange(myRegs, theirRegs)`：戰力與蘭徹斯特交換評估。
- `model.unknown[]`：`{ x, y, radius, kind: 'ford'|'forest'|'high'|'gate'|'alley', lastSeenTick }`。
- `model.keypoints`：`{ fords, gates, highs, forests, wallSegments, alleys, flags, ramTrack }`，每項含「誰控制」。

### 3.3 機動介面（主線定義骨架，兩線各自實作）
每個機動模組匯出：
```
{
  id: 'M3',
  roles: ['flank', 'fix'],                         // 需要的角色
  enter(ctx) -> { ok, assignment: { regId: role } } | null,   // 進入條件與分團
  phases: [ { name, waypointsOf(ctx, regId), done(ctx) } ],   // 階段
  abort(ctx) -> reason | null,                     // 放棄條件（無進展、進入條件不成立）
  finish(ctx),                                     // 收尾（交棒給哪個機動）
  value(ctx) -> number,                            // 評估值：預期交換＋目標價值−風險
}
```
`ctx` 由主線提供：`{ obs, model, tick, assigned, memory }`。單團層只收 `{ target, waypoints, role, abortWhen }`。每條指令的 `intent` 固定格式 `M3/flank/迂迴`。

### 3.4 版本與交付
- 版號：主線奇數、進攻線偶數；整合版沿用主線號。每個凍結版本打 tag `b2-<版號>`（本機 tag，不推送）。
- 交付條件：對應情境 5 種子雙座位全過；typecheck、lint、build、bot --check 過；矩陣不退步超過 10 點。
- 紀錄：COOPERATION.md 每次交付一段（版號、情境結果、矩陣摘要、參數表增減、未完成）。

### 3.5 共同規則
- 不作弊：不依對手代號、種子、評測時間切換；不讀對手原始碼來做針對性判斷。
- 情境判定不可改；認為情境不合理就寫下來請使用者裁決。
- 決策上限 50 ms，警戒 20 ms；模型每秒一次、計畫每兩秒一次、單團每 0.5 秒一次。
- 參賽包永遠不含 b2 原始碼。
