# RTS 對戰引擎與選手 API 規格書 v0.4

Oct 22, 2026 · v0.3 ＋ M3 新內容（**標示「提案」的數值與規則待審**）

## 文件說明

本文件同時是引擎的實作規格，也是給各家 AI 撰寫選手 Bot 的規則文件；範圍為 MVP（1v1 與 4 人混戰）。

- 範圍：1v1、4 人、8 人混戰；工人＋四種戰鬥兵種；七種建築；主堡升級與兩條研究線。
- 所有數值為初始值，平衡測試後調整；調整時版號遞增。
- 文中的「秒」「格」只為方便閱讀；引擎一律以 tick 與「單位」計算。

## 基本單位

全部狀態以整數表示：時間用 tick，長度用「單位」，確保不同平台結果一致。

| 項目 | 定義 |
| --- | --- |
| tick | 邏輯更新一次；1 秒 ＝ 10 tick |
| 格 | 地形格子；1 格 ＝ 1000 單位 |
| 座標 | 原點在地圖左上角，x 向右、y 向下；單位位置為整數單位座標 |
| 格座標 | tileX ＝ floor(x ÷ 1000)，tileY ＝ floor(y ÷ 1000) |
| 距離 | 歐氏距離 |
| 百分比 | 倍率以整數百分比表示（×1.5 ＝ 150），計算後向下取整 |

## 地圖

每場程序生成、依人數旋轉對稱；地形、礦點、瞭望塔與所有起點在開局時全部公開（見開局資料）。

| 規模 | 尺寸（格） | 對稱方式 |
| --- | --- | --- |
| 1v1 | 64 × 64 | 繞中心旋轉 180° |
| 4 人 | 96 × 96 | 繞中心旋轉 90° |
| 8 人（提案） | 128 × 128 | 繞中心旋轉 90° ＋ 沿對角線鏡射（8 個對等起點；分礦朝地圖中心） |

### 地形

| 地形 | 代碼 | 通行 | 可建造 | 視野 |
| --- | --- | --- | --- | --- |
| 平地 | 0 | 可 | 可 | 正常 |
| 阻擋（懸崖、水） | 1 | 不可 | 不可 | 不阻擋 |
| 樹林 | 2 | 可，速度 ×60% | 不可 | 只有觀察者距離 ≤ 2 格時可見 |

### 地圖物件

| 物件 | 數量 | 說明 |
| --- | --- | --- |
| 起點 | 每人 1 | 主堡（3×3）位置，位於基地平台內；平台由阻擋環圍住，朝地圖中心方向有寬 3～5 格的隘口 |
| 主礦區 | 每人 1 | 主堡旁，4 個礦點 |
| 分礦區 | 每人 2 | 平台外，各 4 個礦點，旁邊保留 6×6 格空地供建築 |
| 富礦區 | 每人份 1 | 中立位置（地圖邊緣），2 個富礦點 |
| 瞭望塔 | 1 | 地圖正中心的一個點，佔領半徑 3 格，不佔格、不阻擋、不可攻擊 |

- 礦點佔 1 格，不可通行、不可建造；**枯竭後仍是障礙物**。
- 一般礦點儲量 1000；富礦點儲量 1200。礦區以 areaId 分組。
- playerId 與起點的對應每場依 seed 隨機分配。
- 同一 seed 產生同一張地圖。

## 經濟

唯一資源為「礦」；工人往返礦點與卸貨點的循環由引擎自動執行，選手只決定派誰去哪個礦點。

### 開局

主堡 1 座（已完工）、工人 4 名（主堡外圈最接近主礦區處，**閒置**，需由選手下達 `gather`）、礦 100、指令額度 5。

### 採集循環

1. 工人走到指定礦點旁（工人中心距離礦點邊緣 ≤ 200 單位）。
2. 開採 20 tick，取得 5 礦（富礦點 8 礦）；礦點儲量同步扣除。
3. 走回最近的己方已完工卸貨點（主堡或採集站），抵達（距離邊緣 ≤ 200）即交付入帳。
4. 自動回到同一礦點，重複循環。

- 每個礦點同時只能有 1 名工人開採，其他工人排隊；礦點空出時，**排隊順序中第一位已在礦點旁的工人**開採（被擠開的工人不會卡住後面的人）。每礦點約 2～3 名工人即接近飽和。
- 礦點枯竭時，該礦點的工人自動改採同礦區最近的未枯竭礦點；整區枯竭則送回身上的礦後閒置，並發出 `nodeDepleted`。
- 工人在採集途中被下達其他指令即中斷循環；已攜帶的礦保留，下次採集時先回卸貨點交付。
- 沒有任何已完工卸貨點時，攜帶礦的工人原地等待。

### 人口

| 來源 | 人口上限 |
| --- | --- |
| 主堡（每座，已完工） | +10 |
| 補給站（每座，已完工） | +8 |
| 全場硬上限 | 每位選手 50 |

建造中的建築不提供人口。排入生產時立即佔用人口；人口不足時無法排入。

### 科技（提案）

- **科技等級** ＝ 己方已完工主堡的最高等級（Lv1～Lv3）。建造鍛造所、攻城工坊需要科技等級 2；不足以 `NO_TECH` 拒絕（下指令時檢查）。
- **主堡升級**（`upgrade`）：

| 升級 | 成本 | 時間 tick | 升級後血量上限 |
| --- | --- | --- | --- |
| Lv1 → Lv2 | 150 | 450 | 2000 |
| Lv2 → Lv3 | 250 | 600 | 2500 |

  完成時目前血量增加相同數值。升級期間主堡照常作為卸貨點、提供人口，但生產佇列暫停。
- **研究**（`research`，在鍛造所進行；效果作用於該選手所有戰鬥單位，含之後生產的，不含工人）：

| 研究 | 代碼 | 每級效果 | Lv1 成本／時間／需求 | Lv2 成本／時間／需求 |
| --- | --- | --- | --- | --- |
| 武器 | weapons | 攻擊 +1（倍率前） | 100／400／科技 2 | 175／550／科技 3 |
| 護甲 | armor | 護甲 +1 | 100／400／科技 2 | 175／550／科技 3 |

  同一研究線同時只能在一處進行；研究期間該鍛造所不能做其他研究。
- **取消**：`cancel` 優先取消進行中的升級或研究，全額退還。

### 建造規則

- 由 1 名工人建造；工人須移動到建築邊緣 ≤ 200 單位處，建造期間該工人不可做其他事。
- **下指令時**以「自己已知的資訊」驗證放置：所有佔用格在地圖內、為平地、無礦點、已探索，且不與「己方建築、目前看得到的敵方建築、記憶中的敵方建築」重疊；不符合以 `BAD_PLACEMENT` 拒絕。下指令時不檢查礦量。
- **工人抵達時**以真實狀態再驗證放置並扣除成本；失敗則發出 `buildFailed`（原因 `BAD_PLACEMENT` 或 `NO_MINERALS`），工人閒置。
- 開工時位於佔用格上的單位會被推到附近的空格。
- 建造時血量從 10% 線性增加到 100%；可被攻擊、可被摧毀。
- 建造中途工人被改派，建造暫停；任何己方工人可用 `resume` 接續（已有工人在建造時以 `INVALID_TARGET` 拒絕）。
- 完工後建造的工人閒置。
- 取消建造（`cancel` 建造中的建築）退還 75% 成本（向下取整）。

### 生產規則

- 每座建築的生產佇列上限 5（含正在生產者）；排入時立即扣除成本與人口。
- 取消佇列項目（`cancel` 取消最後一項）全額退還成本與人口。
- 完成的單位出現在建築外圍最接近集結點的可通行格中心（無集結點時取最接近地圖中心者）；若有集結點則自動以 `move` 前往。四周被封住時暫停生產，直到有空位。
- 建築被摧毀時，佇列中的項目不退礦，佔用的人口釋放。

## 戰鬥、視野、移動與碰撞

戰鬥完全確定：無命中率、無暴擊、無投射物飛行時間，勝負只取決於決策。

### 傷害

- 傷害 ＝ max(1, floor((攻擊 ＋ 武器加成) × 倍率 ÷ 100) − 護甲)。護甲與武器加成來自研究（提案），只適用戰鬥單位；防禦塔沒有武器加成。
- 攻擊瞬間生效（含遠程）；冷卻結束才能再次攻擊。
- **射程判定**：單位攻擊方以「攻擊方邊緣到目標邊緣的距離 ≤ 射程」判定（單位為圓、建築為矩形）。例如兩隻長槍兵中心相距 ≤ 200 ＋ 350 ＋ 350 ＝ 900 即可互打。防禦塔以「塔中心到目標邊緣」判定。
- 攻擊需要目標位於己方視野內。
- 同一 tick 的傷害全部結算後才移除死亡者，同歸於盡是可能的。
- 擊殺歸屬：該 tick 對死亡者造成傷害最多的選手；同分取 playerId 小者。

### 視野與迷霧

- 單位以**所在格的中心**為圓心、建築以自身中心為圓心，格中心落在視野半徑內的格子可見；建造中建築視野減半（向下取整）。
- 樹林格：只有觀察者距離該格 ≤ 2 格時才可見；觀察者自己在樹林中，看外面不受影響。
- 懸崖與水不阻擋視野。
- 迷霧三態：未探索 → 已探索但不可見（保留最後看到的敵方建築）→ 目前可見。
- 敵方單位所在格可見即為可見；敵方建築任一佔用格可見即為可見。
- 佔領瞭望塔者獲得以塔為中心、半徑 12 格的視野。

### 移動

- 尋路：在格子上做 8 方向 A\*，不可斜向穿過兩個阻擋格（或建築）之間的縫隙；尋路不考慮其他單位。之後把路徑拉直（開闊地走直線）。
- 追擊移動中的目標時，若直線上沒有阻擋就直接朝目標走。
- 每 tick 沿路徑移動「速度」單位；在樹林格內速度為 floor(速度 × 60 ÷ 100)。
- 目的地不可到達時，移動到最接近的可到達點。

### 碰撞

- 單位以圓形碰撞；允許重疊，每 tick 移動後做一次推擠：重疊的兩單位各被推開重疊量的一半，依單位 id 由小到大依序處理。
- 正在開採或建造的工人不被推動（另一方承受全部推擠）。
- 地形與建築只檢查單位中心點：單位中心不可進入阻擋格、礦點與建築；被推入時退回原位置。

## 通用單位 AI 與勝負判定

選手只下高階指令與姿態，個別單位的索敵、追擊、反擊由引擎以同一套規則處理。

### 姿態

| 姿態 | 代碼 | 行為 |
| --- | --- | --- |
| 積極（預設） | aggressive | 自動攻擊自己視野半徑內（且己方看得到）的敵人；從開始追擊處起最多追 8 格，超過則放棄並走回追擊起點（返回途中不交戰） |
| 防守 | defensive | 只鎖定射程內的敵人；追擊時不離開開始交戰處 3 格，超過則放棄並返回 |
| 堅守 | hold | 原地不動，只攻擊射程內敵人 |
| 撤退 | retreat | 不自動攻擊（明確的 `attack` 指令仍有效） |

- 工人不論姿態都不會自動攻擊，也不反擊；只有收到 `attack`（指定目標）才戰鬥。

### 指令與自動行為

- 移動（`move`）：沿途不主動攻擊；抵達後閒置，駐守點設為抵達處，之後依姿態行動。
- 攻擊移動（`attackMove`）：沿途依姿態自動交戰，敵人消失或放棄追擊後繼續前往目的地。
- 攻擊指定目標（`attack`）：持續追擊直到目標死亡或離開己方視野，不受追擊距離與姿態限制。
- 閒置：依姿態自動交戰。

### 目標選擇

依序比較，前一項相同才看下一項：

1. 正在攻擊自己的敵人優先（該敵人在其冷卻時間內實際攻擊過自己）。
2. 類別：戰鬥單位 > 工人 > 建築。
3. 有兵種倍率優勢（倍率 > 100）者優先。
4. 距離較近者優先。
5. id 較小者優先。

已有目標時，除非目標死亡、離開視野或超出追擊範圍，否則不換目標。防禦塔自動攻擊射程內的敵方單位，目標選擇同上。

### 瞭望塔佔領

- 佔領半徑 3 格內（單位中心距塔 ≤ 3000）只有某一選手的戰鬥單位（工人不算）時，該選手佔領進度每 tick +1；達 100 即佔領。
- 範圍內有多名選手的戰鬥單位、或無人時，進度不變。
- 某選手開始累積時，其他所有選手的進度歸零；原佔領者**立即失去**塔與視野（塔變成無人佔領，直到累積者達 100）。
- 瞭望塔不可被攻擊或摧毀。

### 勝負判定

- 時限：6000 tick（10 分鐘）。
- 淘汰：主堡（含建造中）全數被摧毀即淘汰，其餘單位與建築一併移除。
- 淘汰者名次依淘汰時間，越晚越前；同 tick 淘汰者依淘汰當下的資產分數比較。
- 時限到時存活者依資產分數排名：存活單位成本總和 ＋ 已完工建築成本總和；未花用的礦不計。
- 仍同分時，依比賽 seed 確定性抽籤。
- 1v1 一方淘汰即結束；4 人局、8 人局剩 1 人即結束。

## 選手 API：生命週期

選手是單一 JS 檔案，`export default` 一個 class；每場比賽建立一個新實例，實例欄位即選手記憶。

| 方法 | 呼叫時機 | 輸入 | 輸出 | 時間上限 |
| --- | --- | --- | --- | --- |
| `declare()` | 載入時 | 無 | 宣告物件 | 50 ms |
| `init(data, helpers)` | 開局 tick 0 前，一次 | 開局資料、輔助工具 | 無 | 1000 ms |
| `decide(obs)` | 每 5 tick（tick 0、5、10…） | 觀察資料 | 指令陣列 | 軟 5 ms／硬 50 ms |

### 宣告

```js
declare() {
  return {
    name: '流派名稱',
    version: 'v3',            // 選填
    style: '給玩家看的風格描述',
    knobs: [
      { key: 'rushTiming', name: '進攻時機', description: '…', min: 6, max: 30, default: 12, integer: true },
      // 共 3～6 顆
    ],
  };
}
```

## 選手 API：開局資料與輔助工具

### 開局資料（init 的 data）

| 欄位 | 內容 |
| --- | --- |
| `mode` | `'1v1'`、`'ffa4'` 或 `'ffa8'` |
| `width`、`height` | 地圖尺寸（格） |
| `tiles` | 地形陣列，長度 width × height，索引 ＝ tileY × width ＋ tileX；0 平地、1 阻擋、2 樹林 |
| `mineNodes` | 全部礦點：`{ id, tileX, tileY, rich, areaId, reserve }`（reserve 為初始儲量） |
| `mineAreas` | 全部礦區：`{ areaId, kind: 'main' \| 'expansion' \| 'rich', owner }`（owner 為所屬起點的 playerId；富礦區為 null） |
| `startSlots` | 全部起點：`{ playerId, tileX, tileY }`（主堡左上角格） |
| `watchtowers` | `{ id, x, y }`（單位座標） |
| `me` | 自己的 playerId |
| `players` | 參賽者 playerId 列表 |
| `stats` | `{ units, buildings, multipliers, baseUpgrades, research }`：數值表（同本文件） |
| `matchSeed` | 本場亂數種子 |
| `knobs` | 開局時的旋鈕值 `{ [key]: number }` |

### 輔助工具（init 的 helpers，整場有效）

| 工具 | 說明 |
| --- | --- |
| `pathDistance(fromTileX, fromTileY, toTileX, toTileY)` | 依尋路規則計算的路徑長度（單位；直線一步 1000、斜向一步 1414），只考慮地形、礦點與目前已知建築；起點或終點位於已知建築內時該建築視為可通行；不可達或超出地圖回傳 -1 |
| `canPlace(building, tileX, tileY)` | 依自己已知的資訊判斷可否放置（與下指令時的驗證規則相同） |
| `terrainAt(tileX, tileY)` | 地形代碼；超出地圖回傳 1 |
| `random()` | 回傳 [0, 1) 的確定性亂數，以 matchSeed 與 playerId 初始化；選手唯一可用的亂數來源 |

不提供隘口偵測、礦區排序、戰力評估——這些是選手要比的地方。

## 選手 API：觀察資料

每次決策傳入一個全新的物件（修改它不影響引擎），反映上一 tick 結束時的狀態。

| 欄位 | 內容 |
| --- | --- |
| `tick` | 目前 tick |
| `minerals` | 目前礦量 |
| `supplyUsed`、`supplyCap` | 已用人口（含佇列中）、人口上限 |
| `commandBudget` | 本次可用的指令額度 |
| `myUnits` | 自己的單位（見下） |
| `myBuildings` | 自己的建築（見下） |
| `enemyUnits` | 視野內的敵方單位：`{ id, owner, type, x, y, hp }` |
| `enemyBuildings` | 視野內的敵方建築：`{ id, owner, type, tileX, tileY, hp, level, complete, progress }` |
| `rememberedBuildings` | 已探索但目前不可見的敵方建築最後狀態：同上＋`lastSeenTick`；看到該處已無建築時才會消失 |
| `mineNodes` | 全部礦點 `{ id, reserve }`：可見者為目前儲量，不可見者為最後已知值 |
| `watchtowers` | `{ id, visible, owner, myProgress }`：owner 只在 visible 時有意義（否則為 null） |
| `alivePlayers` | 仍存活的 playerId |
| `events` | 自上次決策以來的事件 |
| `knobs` | 目前的旋鈕值（可能因戰術暫停而改變） |
| `tech` | `{ level, weapons, armor }`：自己的科技等級與研究等級（提案） |

自己的單位：

```js
{ id, type, x, y, hp, stance, group /* 0～9 或 null */, carrying, gatherNodeId /* 或 null */,
  order: { type: 'idle' } | { type: 'move', x, y } | { type: 'attackMove', x, y } | { type: 'attack', targetId }
       | { type: 'gather', nodeId } | { type: 'build', building, tileX, tileY } | { type: 'construct', buildingId } }
```

自己的建築：

```js
{ id, type, tileX, tileY, hp, maxHp, level /* 主堡等級 */, complete, progress /* 0～100 */,
  task: null | { type: 'upgrade', progress } | { type: 'research', research, progress },
  queue: [{ unit, progress /* 0～100 */ }], rally: { x, y } | null }
```

## 選手 API：指令與事件

`decide` 回傳指令陣列，引擎依陣列順序處理；每個指令消耗 1 點額度（**被拒的指令也消耗**，只有 `NO_BUDGET` 不消耗），不論對象是一個單位還是一整支部隊。回傳值不是陣列時視為一個 `BAD_FORMAT`（index 為 -1）。

「單位集合」`units` 可為單位 id 陣列，或編隊代號 0～9。集合中不屬於自己或已死亡的單位自動略過，其餘照常執行。

| 指令 | 格式 | 說明 |
| --- | --- | --- |
| gather | `{ type: 'gather', units, nodeId }` | 工人開始對該礦點採集循環；非工人略過 |
| build | `{ type: 'build', workerId, building, tileX, tileY }` | 工人前往並建造；座標為建築左上角格 |
| resume | `{ type: 'resume', workerId, buildingId }` | 接續己方未完工建築 |
| train | `{ type: 'train', buildingId, unit }` | 排入生產佇列 |
| cancel | `{ type: 'cancel', buildingId }` | 取消佇列最後一項；建築本身建造中則取消建造 |
| rally | `{ type: 'rally', buildingId, x, y }` | 設定集結點（只限能生產的建築） |
| move | `{ type: 'move', units, x, y }` | 移動，沿途不主動攻擊 |
| attackMove | `{ type: 'attackMove', units, x, y }` | 攻擊移動（工人視同 move） |
| attack | `{ type: 'attack', units, targetId }` | 攻擊指定目標（必須是看得到的敵方單位或建築） |
| hold | `{ type: 'hold', units }` | 停下，設目前位置為駐守點 |
| stance | `{ type: 'stance', units, stance }` | 設定姿態 |
| group | `{ type: 'group', group, units }` | 將單位設為該編隊（覆蓋原內容；單位只屬於一個編隊）；units 必須是 id 陣列 |
| upgrade（提案） | `{ type: 'upgrade', buildingId }` | 升級已完工的主堡 |
| research（提案） | `{ type: 'research', buildingId, research }` | 在鍛造所研究 `weapons` 或 `armor` |

所有數值必須是整數；座標必須在地圖內，否則 `BAD_FORMAT`。

### 拒絕原因

| 代碼 | 說明 |
| --- | --- |
| NO\_TECH | 科技等級不足（提案） |
| NO\_MINERALS | 礦不足 |
| NO\_SUPPLY | 人口不足 |
| BAD\_PLACEMENT | 位置不可建造 |
| QUEUE\_FULL | 生產佇列已滿 |
| WRONG\_PRODUCER | 該建築不能生產此單位、建築未完工，或對不能生產的建築設集結點 |
| INVALID\_TARGET | 目標不存在、不可見或不合法（含工人欄位填了非工人、取消時沒有可取消的項目） |
| NOT\_OWNED | 指定的建築或工人不屬於自己 |
| BAD\_FORMAT | 指令格式錯誤 |
| NO\_BUDGET | 超出指令額度 |

`train` 的檢查順序：NOT\_OWNED → WRONG\_PRODUCER → QUEUE\_FULL → NO\_MINERALS → NO\_SUPPLY。

### 事件

每個事件都有 `type` 與 `tick`。

| 事件 | 其他欄位 |
| --- | --- |
| underAttack | `targetId`、`attackerId`（攻擊者看不到時為 null）；同一 tick 同一對象只發一次 |
| unitDied | `id`、`unitType` |
| buildingDestroyed | `id`、`buildingType` |
| enemyKilled | `id`、`owner`、`kind`（'unit'／'building'）、`entityType` |
| buildingComplete | `id`、`buildingType` |
| unitTrained | `id`、`unitType` |
| nodeDepleted | `nodeId`、`areaId`（送給有工人在採、或看得到該礦點的選手） |
| towerChanged | `towerId`、`owner`（無人佔領為 null）；送給看得到瞭望塔的選手與新舊佔領者 |
| playerEliminated | `playerId` |
| commandRejected | `index`（指令在陣列中的位置）、`reason` |
| buildFailed | `workerId`、`building`、`tileX`、`tileY`、`reason`（NO\_MINERALS／BAD\_PLACEMENT） |
| upgradeComplete（提案） | `buildingId`、`level` |
| researchComplete（提案） | `research`、`level` |

## 選手 API：限制、執行模式、確定性與旋鈕

### 指令額度

- 令牌桶：容量 5，tick 為偶數時回補 1（每秒 5 個，約 300 APM）；開局額度 5。
- 每次決策可用額度見 `commandBudget`；超出部分以 `NO_BUDGET` 拒絕。

### 時間上限與錯誤

| 狀況 | 處理 |
| --- | --- |
| decide 超過 5 ms（軟上限） | 該次決策的指令全部作廢 |
| decide 超過 50 ms（硬上限） | 終止選手，整場剩餘時間閒置（防無窮迴圈） |
| declare 超過 50 ms | 選手載入失敗 |
| init 超過 1000 ms | 終止選手，整場閒置 |
| 拋出例外 | 該次視為無指令，比賽繼續 |

### 執行模式

| 模式 | 用途 | 隔離 | 計時 |
| --- | --- | --- | --- |
| 正式模式（official，CLI 預設） | 評測、正式排名 | 每位選手獨立 Worker | 依上表 |
| 批次模式（batch） | 大量統計、遊戲內練習賽 | 與引擎同一執行緒 | 不計軟上限；硬上限於呼叫後檢查 |

- 批次模式**無法中斷無窮迴圈**；開發時請用正式模式驗證。
- 批次模式下原本會超時的決策會被執行，結果可能與正式模式不同；選手應遠低於軟上限運作。

### 確定性

- 引擎在相同 seed 與相同指令序列下必定產生相同結果；回放只保存 seed 與指令紀錄。
- 選手只能使用 `helpers.random()`；`Math.random`、`Date`、`performance` 呼叫即拋例外。

### 選手模組限制

- 單一 JS 檔案（嚴格 ES2020：類別欄位語法等較新語法會載入失敗），不可 import 其他模組或外部函式庫，≤ 200 KB。
- 無法存取網路、檔案、DOM 或其他選手；選手之間無任何溝通管道；同一檔案的兩個選手也不共用模組變數。
- 只能透過觀察資料取得資訊；嘗試讀取引擎內部狀態視為違規。

### 旋鈕

- 在 declare 中宣告 3～6 顆旋鈕：代碼、名稱、說明、最小值、最大值、預設值、整數或小數。
- 範圍內的任何值都必須讓選手正常運作。
- 旋鈕值每次決策透過 `knobs` 傳入，比賽中可能改變，選手必須能正確應對。
- 同一流派的所有版本，旋鈕代碼與範圍保持一致。

## 參賽須知

你要在時限內寫出一隻能在 1v1 與 4 人混戰中取勝的選手，並符合指定的風格方向。

### 交付物

- 單一 JS 模組，實作 declare、init、decide，符合「選手模組限制」。
- 每次有明顯進步就保存一個版本快照（versions/v1.js、v2.js…），附一行變更說明；早期版本也必須可正常執行。
- 最終版本與一份簡短說明：策略概要、各旋鈕用途。

### 條件

- 風格方向：任務會指定一種，最終版本須明顯體現該風格。
- 最低標準：1v1 對基準 Bot 勝率 ≥ 70%（隨機地圖、雙方交換起點）。
- 不得針對特定地圖寫死座標；不得利用引擎漏洞，發現漏洞請回報。

### 可用工具

- `rts-sim` CLI：`match`（指定選手對戰）、`roundrobin`（循環賽）、`mapgen`（看地圖）、`viewer`（回放播放器）。用法見 README。
- `--swap`：1v1 時每個 seed 打兩場並交換起點；`--games` 為總場數（須為偶數）。
- 基準 Bot 原始碼（bots/baseline.js），可作為對手與範例；範例模板（bots/template.js）。
