## 一、一句話

**第二個電競項目「攻防戰」做完了**：一個參照 CS 規則、2D 俯視的 5v5 攻防射擊引擎（規則與選手 API 凍結）、一隻有戰術的基準 Bot、把「角色＋版本＋習慣」衍生成大量選手的公式與強度表，並接上經營層——在正式版經營介面選「攻防戰」，每週的比賽在瀏覽器 Worker 裡真打，打完的每一場都能點「觀戰」重播。

## 二、怎麼玩、怎麼看

```bash
npm run web
```

## 三、目標與原則

- **視野公平是底線**：視錐外、30 格外（開鏡另計）、牆後、煙後、蹲在箱子後面一律看不見，靜步沒有聲音；Bot 只拿得到觀察資料，人類畫面也只畫觀察資料（觀戰模式例外，那是看比賽不是參賽）。
- **確定性**：同一個種子＋同樣的指令＝同一場比賽（整數座標、固定 30 TPS、雜湊）；經營層的閘道關掉 50 ms 逾時判定，結果與機器快慢無關，Node 與瀏覽器 Worker 同一張請求單同一結果。
- **閘道泛化**：經營核心（`src/manage/`）只送名單與種子、只收勝負與逐回合比分，不知道任何賽制內容；人數、能不能觀戰、回合標籤都由賽制自報。
- **凍結**：步驟 5 起規則、數值、選手 API 1.0、引擎 1.0.0 凍結，之後的步驟沒動 `sim.ts`／`config.ts`／`api.ts`／`map.ts`；步驟 7 之後 `bots/` 也沒動。
- **配色紀律**（天使金）：金只給我方、選中、主要行動；紅只給對手與警示；其他白灰。可玩版另有 T 琥珀／CT 天藍兩個陣營色。

## 六、M5 待辦（建議）

1. **主客場換邊**：閘道依種子奇偶決定哪一方上半場當 T（只動閘道與成績單換算，經營層不用改；會改變既有結果）。
2. **版本 5 的實質差異**：基準 Bot 的版本成長在 v4 之後幾乎沒效果，要嘛加大屬性成長、要嘛讓 v5 解鎖戰術旋鈕；強度表重量。
3. **經濟再平衡**：研發報告誤差依閘道場數縮放；豪賭策略的下限保護；練習賽容量與真打耗時的關係。
4. **觀戰體驗**：精華模式（只看交火）、多人視角、回放檔壓縮（決策差分）、從聯賽頁直接看「本週焦點戰」。
5. **合約與多賽季**：`contractSeasons` 目前固定 1；續約、轉會窗口、第二賽季的升降級。
6. **軍團戰真閘道**：照步驟 8 報告第三節的契約變更表接（核心不用改）。
7. **第二張正式地圖**、外部選手參賽包、經營層的選手操控模式（規格書第十四節的第二週候選）。

## 七、合併順序建議

`feature/cs-shooter` 是從 `feature/m4-angel-ui` 開出來的，**包含經營層（`src/manage/`、`src/web/game/` 等）的變更**：名單對名單、`lineupSize`、存檔第 3 版、正式版介面的攻防戰支援。建議：

1. 先合 `feature/m4-angel-ui` 進 main（經營層正式版介面本體）。
2. 再合 `feature/cs-shooter`（攻防戰引擎、Bot、閘道泛化、觀戰；會把經營核心改成名單對名單、存檔升到第 3 版——舊存檔作廢）。
3. `feature/legion-battle`（軍團戰引擎 0.4）與本分支在經營層沒有交集，但都碰 `README.md`、`web/index.html`、`docs/`；軍團戰要接經營層時照本分支的閘道契約（`PlayerSpec`／`SideSpec.players`／`MatchFormat.lineupSize`、`watchable`）寫閘道，經營核心不用改。
4. 合併前在本機跑一次全套檢查（第八節）。
