實作上的取捨：

- 名字洗牌放在玩家席位之後，所以同一種子的戰隊名與玩家席位和改動前相同。

- 名字依序發放用的是「第 n 位選手拿第 n 個」，不另外存游標，開局驗證保證數量足夠。

## 問題與建議

1. **`npcEloBonus` 擋不住玩家撿 SSR（要拍板）。** NPC 只在第一次推進時簽約，玩家在休賽期先動手。
   - 玩家不動手時，NPC 確實會簽走自由市場 SSR 的 92／98。
   - 但玩家先簽的話，一支 SSR 的簽約金平均 225、最高 296，2500 的開局資金足夠；100 局平均簽下 0.97 名，等於全部（每局平均 0.98 名）。
   - 建議二選一：讓 NPC 在開局時先簽一輪（玩家看到的市場已被挑過），或簽約金依品階加價。後者不違反「週薪不看品階」，但要你確認。
2. **v1 的 SSR 和 v1 的 N 同價。** 品階不影響薪資，所以自由市場上 v1 SSR（100 局 29 名）是最划算的標的。養到 v5 要 1984、8 週，單賽段 9 週剛好做得到。這是定案的結果，M5 續約時才會回收，先記著。
3. **品階目前只限制玩家。** NPC 與自動玩家都不會發 `upgradeVersion`，所以上限對 NPC 沒有實際作用，M5 讓 NPC 升版時才會生效。
4. **36／100 局自由市場沒有 SSR。** 玩家起手也沒有 SSR，這些局整季拿不到 SSR。若希望每局都有機會，可保底 1 名。
5. **N 階鎖在 v2 的代價很大。** 射擊包 v2 → v3 差 261（1239 → 1500），玩家起手兩名 N 永遠到不了 v3，全隊 v3 時隊伍平均會低約 104。這會逼玩家換人，方向上合理，但要看新手體驗能不能接受。
6. **同品階的頂點差很多。** 突破手 v5 是 1681，游擊 v4 就有 1699，SSR 突破手比 SR 游擊還弱。這是既有強度表的特性，品階放大了它。

### 英文 ID 的寬度風險（最長 11 字元，例：SleepyGhost）

| 位置 | 風險 | 依據 |
| --- | --- | --- |
| 出賽名單選手卡（`.pc .nm`） | **會溢出**，名字與流派標籤擠不下 | 實測 |
| 陣容列（`.who`） | 沒有溢出 | 實測 |
| 擊殺列（`.sg-feed`） | 低；靠右、無寬度上限，兩個長名字約 260u 內 | 依 CSS 估算，未實測 |
| Tab 計分板（`td.pn`） | 低；半張表的欄寬足夠，但沒有 ellipsis | 依 CSS 估算，未實測 |
| 頭上名字（`render.ts` 的 label） | 中；名字變長後和血條、相鄰選手的名字較容易疊在一起 | 依程式推估，未實測 |

另外，`game.css` 不少名字樣式帶 `letter-spacing: 0.06～0.1em`，是為中文字距設的，英文 ID 會顯得過鬆，且寬度多約 10%。

## M5 接口

- **依戰績調薪：** 續約時由 `Player.elo`、`games` 算新週薪，`weeklySalary` 已是獨立欄位，升版倍率不用動。
- **續約時品階的角色：** 品階維持開局固定。續約可把「距上限還有幾版」當談判籌碼，用 `KnownPlayer.maxVersion − version` 就算得出來，例如未到頂的高品階要價較高。
- **`contractSeasons`：** 已固定為 1，M5 才開始遞減。
- **新一季的選手來源：** `makePlayer` 只在開局呼叫，名字依序發放的前提也是開局一次性。M5 若要補新人，名字庫 120 個扣掉每局 58 人還有 62 個，但要改成把洗好的名單與游標存進狀態。
