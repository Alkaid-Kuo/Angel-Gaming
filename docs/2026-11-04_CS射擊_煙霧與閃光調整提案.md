# 煙霧與閃光調整（提案）

日期：2026-11-04。狀態：**提案，尚未動工**。基底：main `0404ef5`（Bot 2.6.2 已合併）。

起因：使用者實玩後問到穿煙射擊、手榴彈炸煙、煙滅火，以及閃光躲避的時間基準。這份提案分兩部分，可以各自決定：

- **規則**（引擎）：要改規則版本、重量強度表。
- **Bot**：不改規則，只改基準 Bot。

背景研究見：

- [閃光進點與發槍保槍研究](2026-11-04_CS射擊_閃光進點與發槍保槍研究.md)

## 一、現況

| | 我們的引擎（規則 1.2） | CS2（攻略與媒體轉述，未找到 Valve 原文） |
| --- | --- | --- |
| 煙的大小與時間 | 半徑 3 格，1 秒內擴散到滿，持續 18 秒；視線上是一個圓 | 立體煙，約 18～20 秒 |
| 子彈穿過煙 | 子彈照穿、傷害不減；**不開視野**。看不到開槍的人就看不到他的彈道，打中看不見的人自己也當作沒打中 | 子彈在煙裡**暫時打開缺口**，隨即合起來。各來源描述不完全一致 |
| 手榴彈與煙 | 手榴彈傷害不受煙阻擋（`heBlockedBySmoke: false`）；**不會**炸散煙 | 手榴彈炸出**暫時的大缺口** |
| 煙與火 | 煙和火圈重疊，整團火熄滅；燃燒彈落在煙裡點不著 | 相同 |
| 炸彈爆炸 | 不影響煙和火 | 近期更新後，爆炸會吹散煙、熄滅火 |

| 出手聲音 | 沒有：只有道具落地、彈牆聲與爆炸聲 | 有出手與彈跳聲 |

Bot 的現況（2.6.2）：
- **閃光**：T 丟之前喊 `E:flashing`、丟出喊 `E:flash`（帶爆炸時間）。隊友依警覺多等 0～4 個決策才反應；在爆點 15 格內又看得到爆點的人，會走到 7 步內看不到爆點的格子躲。
- **飛行中的閃光**：看得到（自己視野內或 2 格內），但只有位置，沒有是誰丟的、沒有速度。目前只用來判斷「這個入口已經有人丟了」，**躲閃光時還沒用上**。
- **煙**：CT 會穿煙盲射；**沒有人會用煙去滅火**。
- **手榴彈**：只丟向聚集的敵人（以及佯攻）。

## 二、規則調整提案（需要使用者決定）

### R1. 手榴彈炸開煙霧（建議做，優先）

- **規則**：手榴彈在煙裡或煙邊爆炸時（爆點到煙心 < 煙半徑 ＋ 1 格），那顆煙的視線半徑立刻縮到 30%，接下來 1.5 秒線性長回原本大小。
- **為什麼用「縮小」而不是「挖洞」**：
  - 我們的煙在視線上是一個圓，縮小只要改半徑，計算簡單、結果可預期。
  - 觀察資料本來就回報「煙此刻的實際半徑」，**選手 API 不用改**，Bot 看得到煙變小。
  - 挖洞要在圓裡再挖圓、逐段判斷，視線計算變複雜。
- **對玩法的影響**：
  - CT 可以用一顆手榴彈換 1～2 秒視野，打煙後的人；T 也一樣。
  - 煙的價值略降，手榴彈的價值上升。
- **代價**：
  - 規則版本 1.2 → 1.3。
  - T 回合勝率窗口與強度表要重量（基準 Bot 會先配合 B4）。
  - 盲射、煙霧相關情境要重跑。
- **建議數值**：縮到 30%、1.5 秒復原，先用模擬量。

### R2. 子彈打開缺口（建議暫緩）

- CS2 各來源描述不一致；我們的子彈是瞬間命中的線段，要模擬「打出一條短暫的縫」，得替每條彈道加一個持續數個 tick 的細長缺口，視線計算的成本與複雜度都較高。
- 盲射 2.6 已經做了，而且盲射的人看不到煙後，正是這條規則想保留的不確定性。
- 建議 R1 做完、試玩後再決定。

### R3. 炸彈爆炸吹散煙、熄滅火（不做）

我們的回合在炸彈爆炸時就結束，地上的煙火會在下回合開始時清掉，這條沒有玩法影響。

### R4. 閃光時間（不改）

我們的致盲時間比 CS2 短，背對 0.3 秒也比 CS2 的約 1 秒寬鬆。但閃光的平衡是 Bot 2.5～2.6 一路調出來的，改動等於重新開始，建議不動。CS2 的角度表也沒能用遊戲檔驗證。

## 三、Bot 調整提案（不改規則也能做）

| | 內容 | 預期效果 | 大小 |
| --- | --- | --- | --- |
| B1 | **看到隊友的閃光就躲**：視野內出現飛行中的閃光，而且不是敵方的（我方剛宣告、或從隊友那側飛來），就從第一眼看到的時間推算爆炸時間（第一眼 ＋ 引信 1.5 秒，保守估）來躲。看不到的人照舊靠喊話 | 看得到的人提早反應，比喊話準；被隊友閃到的人次再降 | 約 0.6 KB |
| B2 | **突破手卡炸開那一刻拉出**：突破手在轉角外等，算好「爆炸時間 − 走到能看到入口的時間」才拉出（職業的「炸開瞬間拉出」）；現在是炸開後 2 秒內直接衝 | 閃光後 3 秒內擊殺回到 2.5 的 0.325 以上（2.6.2 是 0.294） | 約 0.8 KB |
| B3 | **T 用煙滅火**：CT 燒住入口時，帶煙的 T 對著火丟煙，再照常進點（現在是等火熄或繞路） | 減少 T 被燃燒拖住；配合 CT 先燒後煙的守法 | 約 0.6 KB |
| B4 | **手榴彈開煙**（R1 有做才做）：<br>• CT：知道煙後有敵人（盲射的條件）時，先丟手榴彈再打。<br>• T：CT 封住入口的煙，執行時先丟手榴彈 | 讓 R1 在 Bot 對局裡真的被用到 | 約 0.8 KB |

選手模組目前 256,666 bytes，上限 262,144，**只剩約 5.4 KB**。B1～B4 合計約 2.8 KB，裝得下；再往後就要先處理上限（提高上限或壓縮產物），這要使用者決定。

## 四、量測與驗收（沿用 2.6 的方法）

- **回合勝率窗口**：v3、v5 鏡像各 200 場，都在 48～55%；對 2.5 直接對戰 v3、v5 各 40 種子。
- **閃光**：
  - 同時疊閃（0.5 秒內、4 格內）維持 ≤ 8%。
  - 被隊友閃到（40 場人次）不高於 2.6.2 的 11。
  - 閃光後 3 秒內擊殺 ≥ 0.325。
- **新情境**：
  - 「煙滅火」：CT 燒住入口，帶煙的 T 會先滅火再進。
  - 「手榴彈開煙」（R1）：煙後有敵人時，CT 先丟手榴彈再打，煙變小的那段時間裡打得到。
- 情境 P0～P13、T1～T27、R1～R6 全過，全案 vitest 只容許既有的 S16。
- R1 若採用：規則版本、存檔與 API 文件同步更新，強度表與 T 窗口重量。

## 五、建議順序與要使用者決定的事

建議順序：**先做 B1～B3（不改規則）→ 量測 → 再決定 R1**。R1 若採用就連同 B4 一起做。

要決定的：
1. R1（手榴彈炸開煙霧）要不要做？數值先用 30%／1.5 秒可以嗎？
2. R2（子彈開縫）同意暫緩嗎？
3. B1～B3 要不要先做？
4. 選手模組上限快滿，之後要提高上限，還是先壓縮產物？
