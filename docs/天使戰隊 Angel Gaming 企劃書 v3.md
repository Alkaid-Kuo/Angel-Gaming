# 天使戰隊 Angel Gaming 企劃書 v3

Oct 22, 2026 · @ALK

## 概要

《天使戰隊 Angel Gaming》是單機經營遊戲：玩家創立一間新創電競公司，發掘、挖角、培訓選手，參加虛構 RTS 的電競賽事，靠成績拉贊助；公司破產即遊戲失敗。

- 名稱：天使戰隊／Angel Gaming——「天使」取自天使投資人，英文讀起來像一支真實戰隊。正式上架前需做商標檢索。
- 類型：2D 電競經營 ＋ RTS 觀戰
- 平台：先做 HTML 原型，之後評估轉 Unity
- 世界觀：選手是人類電競選手；實作上每位選手背後是各家 AI 撰寫的 Bot，遊戲內不提及 AI。
- RTS 是遊戲中的遊戲，風格獨立（中世紀兵種），名稱待定。
- 主軸：Bot 對戰的觀賞性，以及資訊不對稱下的經營判斷——新創沒錢跟豪門硬拚，只能靠情報贏。

## 三層架構與世界觀對照

勝負只取決於選手的決策品質：單位行為由引擎統一處理，所有選手共用。

| 層 | 負責者 | 內容 |
| --- | --- | --- |
| 引擎 | 開發者，所有人共用 | RTS 規則、通用單位 AI（尋路、索敵、反擊、自動採集） |
| 選手 Bot | 各家 AI 撰寫 | 像人類玩家一樣下決策：蓋什麼、生什麼、部隊去哪 |
| 玩家 | 遊戲玩家 | 電競公司老闆：發掘、挖角、培訓、排陣、下注 |

| 實作 | 世界觀包裝 |
| --- | --- |
| 一條 Bot 版本線 | 一個流派（打法） |
| 版本 v1 → vN | 選手的職涯成長 |
| 升版 | 培訓後選手進步 |
| 旋鈕研發（跑模擬） | 練習賽 ＋ 教練團研究戰術 |
| 模擬算力 | 訓練中心等級（每週練習賽場數） |
| 旋鈕預設的小偏移 | 選手的個人習慣 |
| 旋鈕擾動 | 選手狀態起伏、老化 |

## 選手製作：AI 軍備競賽與流派模式

目標約 25～30 個流派（5 家 AI × 每家 5～6 種風格方向），以流派模式撐起數百名選手。執行細節見「軍備競賽執行手冊」。

### 軍備競賽

- 開發者先做一隻基準 Bot，各家 AI 的作品至少要能打贏它（1v1 勝率 ≥ 70%）。
- 各家 AI 使用同一份規格書、同一時限（正式約 5 小時）、同硬體、同一份提示詞模板。
- 每次執行指定一種風格方向（速攻、快速擴張、塔防龜縮、騷擾經濟、適應反制、控圖），避免收斂到同一套解。
- AI 以 headless CLI 自我對戰迭代，並保存版本快照 v1 → vN，即該流派的成長線。

### 流派模式

- 一條版本線 ＝ 一個流派，不是一個人。
- 一名選手 ＝ 流派 ＋ 目前版本 ＋ 個人習慣（旋鈕預設的小偏移）。
- 同流派可同時有多名選手：有人在 v3 剛出道，有人在 v8 正值巔峰。
- 新人永遠可以從某流派的 v1 重新出發，選手不會用完。

## RTS 對戰與選手介面（摘要）

完整規則、數值與選手 API 以「RTS 對戰引擎與選手 API 規格書」為準；本節只列重點。

### RTS 對戰

- 規模：1v1、4 人、8 人（8 人於 M3 加入）；每隊每場派 1 名選手。
- 地圖：每場程序生成、旋轉對稱；地形、礦點、起點開局全知，敵人動向靠偵察。
- 移動：自由移動、整數座標，尋路走格子；軟碰撞。
- 經濟：單一資源，工人自動往返採集；礦點枯竭逼迫擴張；人口上限每人 50。
- 單位：工人＋長槍兵、弓兵、騎兵剋制三角；攻城車等於 M3 加入。
- 建築：主堡、採集站、補給站、兵營、防禦塔；主堡升級、攻城工坊、鍛造所於 M3 加入。
- 戰鬥完全確定，無命中率與暴擊；三態戰爭迷霧；樹林可伏擊；中央瞭望塔提供視野。
- 通用單位 AI：積極、防守、堅守、撤退四種姿態。
- 勝負：失去所有主堡即淘汰；10 分鐘時限到依資產分數排名。

### 選手介面

- 每 0.5 秒決策一次，每秒最多 5 個指令（約 300 APM）。
- 選手看到的資訊與人類玩家相同；引擎提供尋路距離等基礎工具，但不提供局勢分析。
- 旋鈕每次決策重新傳入，可因戰術暫停而改變。
- 回放保存「比賽 seed ＋ 指令紀錄」，以引擎重新模擬。

## 觀戰呈現

仿電競轉播：自動導播鏡頭＋轉播資訊列，並提供快轉與精華模式，讓玩家一季能看很多場。

| 鏡頭模式 | 說明 |
| --- | --- |
| 自動導播（預設） | 跟著最大交戰走；主堡遭攻擊、分礦被拆時切過去；每個鏡頭至少停留數秒 |
| 跟隨自家選手 | 鎖定玩家自己的選手 |
| 自由鏡頭 | 手動拖動、縮放 |

- 畫面資訊：頂部選手列、小地圖（上帝或選手視角）、戰力曲線、事件字幕。
- 時間控制：1x／2x／4x、跳到下一次交戰、精華模式、直接看結果。
- 觀戰時玩家只能使用自家的戰術暫停（每場 2～3 次）；不做即時下注、不做選手內心話。
- 美術以觀戰可讀性優先：8 種隊伍顏色可辨（含色盲友善），兵種輪廓縮小後仍可辨認。

## 公司經營

經濟循環：發掘／挖角 → 培訓 → 參賽 → 獎金與贊助；情報 → 下注與預測 → 收益，全部回流到同一個資金池。現金歸零即破產，遊戲失敗；介面持續顯示「資金跑道」。

### 收入

| 來源 | 說明 |
| --- | --- |
| 比賽獎金 | 依賽事等級與名次 |
| 下注 | 他人的比賽可自由下注；自己的比賽只能買自己贏 |
| 賽事預測 | 大型賽事開放 Pick'em（分組與淘汰賽預測） |
| 贊助 | 隨名氣增加，每月入帳；可附帶條件 |
| 融資 | 以股份換資金，附帶 KPI |

支出：選手薪資、員工薪資、設施升級與維護、簽約金與轉會費、情報、盃賽報名費。財務每週結算。

### 下注規則

- 賠率只依公開戰績計算；玩家買情報看得更多，才有贏過莊家的空間。
- 比賽 seed 賽前未知，模擬只能得到勝率，不會得到確定答案。
- 下注上限隨戰隊等級與名氣提高；莊家抽成，長期亂押必虧。

### 員工與設施

| 項目 | 影響 |
| --- | --- |
| 教練 | 練習賽研發的效率 |
| 球探 | 新人潛力判斷的準確度與發掘範圍 |
| 分析師 | 情報的詳細程度 |
| 訓練中心 | 每週能打的練習賽場數 |
| 辦公室 | 員工人數上限 |

### 融資與董事會

- 種子輪 → A 輪 → B 輪…，投資人給錢換股份，附帶 KPI；未達成則下一輪條件變差。
- 董事會信心值公開顯示，受成績與 KPI 達成度影響。
- 持股低於 50% 時，每個賽段結束有機率被開除（遊戲失敗），信心值越低機率越高；持股 50% 以上不會被開除。

## 選手經營

新創靠球探找被低估的新人（Moneyball 路線），再用培訓與戰術研究把他們養成主力。

### 取得管道

| 管道 | 時機 | 說明 |
| --- | --- | --- |
| 新秀發表會 | 休賽期 | 新人以某流派 v1 出道；潛力隱藏，靠球探報告判斷；各隊競價簽約 |
| 私下簽約 | 發表會前 | 球探先發現的新人可提前簽下 |
| 轉會 | 轉會窗口 | 向其他戰隊報價，對方可接受、拒絕或還價一次 |
| 自由選手 | 隨時 | 合約到期或被釋出的選手，便宜但多為舊版本 |

潛力 ＝ 該流派後續還有多少版本、最終版多強。

### 前期保護

- 開局給 2～3 名起始選手與一筆資金。
- 新創聯賽裡同場競價的是同樣窮的 NPC；豪門主要走轉會市場。
- 各隊有陣容上限與薪資上限。

### 合約與培訓

- 合約：期限（以賽季計）＋年薪；到期需續約，否則離隊。
- 升版：培訓讓選手沿流派成長線前進。
- 練習賽研發：花費週數跑大量模擬，搜尋針對地圖類型、對手或規模的最佳旋鈕值，產出戰術預設；有特化 vs 泛用、樣本誤差、升版使預設失效等取捨。
- 賽前選擇戰術預設；賽中可戰術暫停切換。

### 狀態與波動

依序評估，必要時才加入：先量測勝率分布 → 賽前公布的環境變數 → 賽前公開的選手狀態（以旋鈕擾動呈現）。

### 生涯循環

老化以旋鈕擾動呈現表現下滑；老將退役，新人從某流派 v1 重新出發，聯賽持續新陳代謝。

## 賽季與賽事

一個賽季＝一年，仿 LoL：兩個聯賽、季中邀請賽、世界盃；以週推進，一季約 2～3 小時遊玩。

### 時間推進

平日經營（研發、交易、情報、下注），週末比賽日；研發與球探消耗週數，在推進時間時於背景完成。

### 賽季流程

1. 休賽期：轉會窗口、新秀發表會
2. 春季聯賽（約 10 週）
3. 季中邀請賽
4. 夏季聯賽（約 10 週，季中有短轉會窗口）
5. 世界盃：小組賽＋淘汰賽，開放 Pick'em

### 聯賽與賽制

| 級別 | 說明 |
| --- | --- |
| 新創聯賽 | 起點，獎金少，對手弱 |
| 職業聯賽 | 中間層 |
| 頂級聯賽 | 獎金與贊助最高，前幾名晉級世界盃 |

- 每個賽段結束升降級；另有需繳報名費的盃賽／邀請賽。
- 每個比賽日混合 1v1 循環與多人混戰，依名次給積分。
- 出賽限制：同一比賽日每位選手只能出賽一場。

### NPC 戰隊

規則型 AI，各有經營個性：豪門、青訓派、數據派、守財奴。

### 長期結構

- 單一長期生涯，可多存檔；里程碑為世界盃冠軍與公司估值達獨角獸。
- 終點是 meta 被完全掌握；延長路線為退役與新人循環、規則改版後重跑軍備競賽、遠期開放玩家匯入自製 Bot。

## 開發計畫與相關文件

MVP ＝ 可觀戰的 AI 對戰 Demo（M0～M3），先驗證風險最高的三件事：對戰好不好看、AI 能否寫出能打且風格不同的選手、模擬速度是否足夠；經營層放在 MVP 之後。

### 里程碑

| 階段 | 內容 | 過關條件 |
| --- | --- | --- |
| M0 引擎核心 | headless 規則引擎、地圖生成、選手沙盒、回放、基準 Bot、CLI | 確定性測試全過；效能達標；基準 Bot 穩勝隨機 Bot |
| M1 人類可玩 | 瀏覽器畫面、人類操作、回放播放器 | 開發者親自對戰覺得好玩 |
| M2 小規模軍備競賽 | 參賽包、2 家 AI × 2 風格試跑 | AI 作品勝基準 Bot ≥ 70%、風格可區分、規則未被誤讀 |
| M3 觀戰體驗 | 自動導播、轉播資訊、精華；8 人局與延後內容 | 連看 10 場不無聊；勝率分布有懸念 |
| M4 經營最小循環 | 單一聯賽、陣容、資金、下注、週推進、破產 | 玩完一個賽段想繼續 |
| M5 完整內容 | 正式軍備競賽 25～30 流派、三級聯賽、轉會、員工、融資、世界盃 | — |

M5 之後評估是否轉 Unity。

## 技術方向

規則引擎以 TypeScript 寫成純邏輯、可 headless 執行，Node 與瀏覽器共用；選手以 JavaScript 撰寫。

- 正式比賽與軍備競賽在 Node 執行，每位選手獨立 Worker 並計時。
- 遊戲內練習賽、NPC 比賽使用批次模式（同一 Worker、不計時），以速度優先。
- 確定性：整數運算＋固定 seed；回放 ＝ seed ＋ 指令紀錄。
- 轉 Unity 時以 Jint 執行同一份 JS 選手。
- 最早期先量測每秒模擬場數，決定遊戲內練習賽的週數換算。
