## 二、要改的東西

### 2.1 地圖

- `maps/shooter/redrock.json`：由 `redrock2-v4-doorAB.json` 改名而來，`id: "redrock"`、`name: "赤岩舊城"`，區域代號照新地圖報告第七節定案不改；`MAPS.redrock` 改讀它；`REDROCK_LAYOUT`（TS 版赤岩鎮）刪除；`DEFAULT_MAP_ID`、`GATEWAY_MAP_ID` 維持 `'redrock'`，所以閘道、經營層、試玩不用改路徑。
- 沙城 `DUST_LAYOUT`：**留在 `map.ts` 但不進玩家面**：試玩頁下拉、文件、首頁都不出現；只給 `acceptance.ts`、`ai-scenarios.ts`、測試與強度腳本用。（若使用者改口要砍，另開任務，因為 Bot 驗收情境要全部搬家。）
- 試玩頁地圖下拉：只列正式地圖；正式地圖只有一張時仍保留下拉（之後地圖池用）。
- **風格接口**（這一包只做資料結構與一張圖的資料，不做第二種風格）：
  - `MapLayout` 加選用 `theme?: string`（材質族代號，預設 `'redrock'`）與 `decor?: { wells?: Rect[]; tarps?: Rect[]; … }`（擺設，格座標）。
  - 美術側 `materials.ts` 的 `DECOR` 硬編碼表改成讀地圖 JSON 的 `decor`；`ZONE_OF` 查表改成優先讀 `areas[].material`，查不到才退回代號表。`MapInfo` 不動、API 不升。
  - 美術側烘焙的調色盤與材質畫法依 `theme` 分檔（`themes/redrock.ts`），新風格＝新增一個檔，不改引擎。
- 赤岩舊城補擺設：井、帆布、包點塗裝位置寫進 JSON `decor`（美術 A 報告第四節第 8 條說 v3 座標對不上，要重擺）。

### 2.2 賽制

- `src/shooter/gateway.ts` 的 `FORMAT_OPTIONS` 加 `'shooter-mr6': { roundsPerHalf: 6, winRounds: 7 }`（加時沿用 `ROUND.overtime`）；內容包 `content-shooter.ts` 的聯賽賽制改指向它；`shooter-mr12` 保留。
- `roundPhase`（上半場／下半場／加時 n）與 `estimateWeekMs`、`estMsPerRound` 跟著賽制長度算，不寫死 24 回合。
- 經營層介面與觀戰頁的回合格數、半場分隔都讀賽制，不寫死。
- 強度表的「回合勝率換整場勝率」係數 k 在 MR6 下重擬合（強度腳本輸出）。

### 2.3 凍結時間

- `ShooterMatchOptions` 加選用 `freezeTicks?: number`；`ROUND.freezeTicks` 預設改為 10 秒（有人類的試玩）；閘道 `gatewayDriverOptions` 傳 3 秒；回放檔頭 `header.freezeTicks` 一併保存，重播照檔頭。
- `rules.freezeTicks` 已在選手 API 的開局資料裡，Bot 讀它而不是常數（`tactics.js` 已是）；**不改 `bots/`**，但要跑一次 3 秒下的全部驗收情境確認 Bot 行為正常（指揮在凍結時間選計畫、買槍是否來得及）。
- `buyTicks`（從回合開始算 20 秒）不變；驗收情境與 `acceptance.ts` 裡所有 `ROUND.freezeTicks` 改讀該場的規則。
- 觀戰頁「跳到下一回合」與回合橫幅不受影響，但要實測一次 3 秒凍結的觀戰畫面不會閃過。

### 2.4 版本與存檔

- `SHOOTER_ENGINE_VERSION` → `1.2.0`；`SHOOTER_API_VERSION` 維持 `1.1`（開局資料形狀沒變；若 2.1 或 2.3 讓形狀變了才升）。
- `SAVE_VERSION` → 4；舊存檔開啟時標題畫面訊息改成「地圖與賽制已更新，舊存檔無法沿用」。
- 回放：`engineVersion` 不符時 CLI 與觀戰頁要有明確訊息，不能默默在新圖上重播。
- 規格書：第四節（地圖）、賽制節、第九節修訂紀錄（1.2：地圖、MR6、凍結）、第十三節檔案表。
