# CS 射擊 Bot 3.0 路線圖（草案）

2026-11-06 使用者定調：最終目標是**堪比職業選手的 Bot**。Bot 2.7／2.8 與批 4 都是過渡版，升版後會解決的問題不細究。本文件是後續 Bot 工作階段的共同依據。

## 一、原則

- 職業級＝一張量得到的指標表（第四節），不是形容詞。
- 職業級是天花板：滿屬性、滿熟練度、教練配得好的隊伍達到它；M5 的屬性、熟練度、教練偏好從天花板往下折。
- 驗收仍用直接指標與分岔量測，整場勝率只確認「沒退步」。
- 保留：模擬確定性（同種子同結果）、無純隨機（只用種子化亂數流）。
- 產物上限 256 KB **可擴大**（使用者 2026-11-06 同意），需要時提出要擴到多少。
- 引擎設計不遷就 Bot；Bot 需要而引擎缺的機制（聲音、資訊共享等）由引擎補。

## 二、架構（三層）

1. **資源層（乙）**：道具是組的資源。凍結時依戰術配用途、時機、丟的人；人死或用掉時重分配；個人層丟道具前問資源層。
2. **效用式個人層（丙-1）**：每 0.3～0.5 秒或事件觸發一次決策。候選動作固定一組（守、推進、探頭、退掩體、補槍位、丟道具到某點、轉點、下包／拆包），效用＝特徵加權和（危險圖、掩體、隊友距離、剩餘時間、炸彈狀態、敵情新鮮度、計畫目標距離、教練偏好、熟練度），加承諾成本防抖，每次決策記錄前三名與分數。
3. **規劃式指揮層（丙-2）**：中局依資訊重發計畫；跨回合對手模型。

權重用自我對戰的演化式搜尋決定（丁-1），不手調。不走神經網路強化學習（M5 要能操縱、要可解釋、算力與管線都不合）。

| 2 | 開局對槍勝率 | 每回合第一次擊殺是我方 ÷ 回合數 | 隊伍 52～58% | 首殺方贏已量 |

## 五、已決與未決

- 已決（使用者 2026-11-06）：256 KB 現階段夠用就不升；之後開發需要時由審查端自行調升，不必再問。聯賽黑盒的大小上限比照最終 Bot 的大小，不另訂。
- 已決（使用者 2026-11-07）：產物上限擴到 288 KB（294,912 bytes）；`RULES.botModule.maxBytes` 全平台共用（PR #36）。
- 引擎盤點：聲音、視野、資訊共享、道具傷害是否足以支撐第 3.5 階的資訊模型。
- 指標表的絕對值由使用者與審查端在 Bot 3.0 開工前定案。

## 六、Bot 3.0 第一步：資源層介面（2026-11-07，分支 claude/cs-bot-3-0）

1. **道具計畫**：凍結時指揮層依戰術產生道具計畫，每顆道具一筆 `{owner, kind, purpose, target, trigger}`。
   - purpose 例：entryFlash、entrySmoke、holdSmoke、fireBackup（保留給滅火）、chokeMolotov、retakeSmoke、retakeFlash。
   - target 是入口或點位。
   - trigger 是時機：到門口 N 格、聽到執行、入口被火蓋住、回防開始。
2. **需求表**：每個戰術一張，買法階段就照需求表決定誰買什麼。
   - rush：兩閃進點＋一煙備援。
   - split：主路一煙、兩路各一閃。
   - default：封煙一顆＋滅火備援一顆。
   - CT：關鍵路口一火；回防一煙一閃保留。
3. **claim**：個人層丟道具前問資源層 `claim(playerId, kind)`，拿到自己的那筆才丟，沒有就不丟。人死或用掉時重新分配：備援優先補給離目標最近、身上有該道具的人。
4. **隊友閃光致盲**（default 40%）在這裡解：閃光的 trigger 綁「跟進者的位置」而不是丟的人的位置，炸開時跟進者不在視錐內。
5. **回防必走道具**：retake 計畫固定先用 retakeSmoke 封另一入口，或先 retakeFlash 再進，不再空手硬衝。

**直接指標**（各 2 × 200、鏡像、附區間）：
- 被火蓋住的回合，20 秒內進點率。
- 道具浪費率：閃到零人、煙沒蓋到任何路線。
- 隊友致盲秒數占比：目標 default ≤ 20%。
- 回防回合有用道具的比例。
- 整場對 2.8 不退步。

**其他約束**：
- 產物 256 KB，需要就報要擴到多少。
- 確定性、無純隨機維持。
- 先寫設計（含資料結構與各戰術需求表），貼 PR 草稿給審查端審，審過再動手。
