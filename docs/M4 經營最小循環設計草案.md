# M4 經營最小循環設計草案

Oct 22, 2026 · 草案，待審（尚未實作）

企劃書 M4 的範圍是「單一聯賽、陣容、資金、下注、週推進、破產」，過關條件是「玩完一個賽段想繼續」。本草案把企劃書的經營層收斂成可在 M4 實作的最小循環，並列出需要你決定的事項。

## 一、最小循環

```
休賽期（簽約）→ 每週：平日經營 → 週末比賽日 → 財務結算 → 下一週 … → 賽段結束（名次、升降級預留）
```

- **平日**：查看下週賽程與對手情報、調整出賽陣容與戰術預設、下注、安排練習賽研發（消耗週數，背景完成）。
- **比賽日**：所有比賽以引擎批次模式模擬（seed 賽前未知）；玩家可選擇觀戰自家比賽（M3 的觀戰畫面）或直接看結果。
- **結算**：獎金、下注、薪資、設施維護入帳；現金 < 0 即破產（遊戲失敗）。

## 二、資料模型

| 物件 | 欄位 |
| --- | --- |
| 流派 | 代號、風格描述、版本線（v1～vN 的 Bot 檔）、旋鈕表；來源 AI 不顯示 |
| 選手 | 姓名、流派、目前版本、個人習慣（旋鈕預設的小偏移）、潛力（隱藏）、合約（年薪、剩餘賽季）、狀態（旋鈕擾動，M4 先不做） |
| 公司 | 名稱、現金、名氣、設施等級（訓練中心）、陣容（上限 5） |
| 聯賽 | 8 隊（玩家 1 ＋ NPC 7）、賽程、積分榜 |
| NPC 戰隊 | 性格（豪門、青訓派、數據派、守財奴）決定簽約與出賽策略 |

## 三、賽制（新創聯賽，M4 只做一個賽段）

- 8 隊、10 週。每個比賽日：每隊派 1 名選手打 1 場 1v1（單循環 7 週）＋ 1 場 4 人混戰（後 3 週）。
- 積分：1v1 勝 3 分；4 人局依名次 4／2／1／0 分。
- 出賽限制：同一比賽日每位選手只能出賽一場（企劃書規定）。

## 四、經濟數值初版（全部待審，M4 實測後調整）

| 項目 | 初版 |
| --- | --- |
| 起始資金 | 1,000 萬 |
| 選手年薪 | v1 新人 40～80 萬；版本每高一級約 ×1.3 |
| 週薪資支出 | 年薪 ÷ 52 |
| 比賽獎金 | 1v1 勝 15 萬；4 人局第 1 名 25 萬、第 2 名 10 萬 |
| 賽段名次獎金 | 第 1 名 300 萬，依序遞減 |
| 贊助 | 每週 名氣 × 1 萬 |
| 訓練中心 | Lv1～Lv3，每週維護 5／12／25 萬 |
| 破產 | 週結算後現金 < 0 |

## 五、下注

- 賠率只依公開戰績計算：以聯賽內的公開 Elo 估計勝率 p，賠率 ＝ (1 − 抽成) ÷ p，抽成 8%。
- 他人的比賽可自由下注；自己的比賽只能押自己贏；單注上限依名氣。
- 玩家的優勢來自情報：買情報可看到對手近期的旋鈕預設與版本，自己用練習賽模擬估計真實勝率。

## 六、練習賽研發（與引擎的接點）

- 旋鈕研發 ＝ 在 Web Worker 用批次模式跑大量模擬，搜尋對某對手／地圖規模的最佳旋鈕值，產出「戰術預設」。
- 換算依 M0 bench：1v1 每核心每秒約 6.5 場、4 人局約 1.7 場。建議遊戲內以「每週可跑場數」呈現訓練中心等級：Lv1 200 場、Lv2 600 場、Lv3 1500 場（實際運算在推進時間時於背景完成，玩家等候 ≤ 數秒）。
- 樣本誤差：顯示勝率估計的信賴區間，讓「特化 vs 泛用」有取捨。

## 七、需要你決定

| 事項 | 選項（建議以粗體標示） |
| --- | --- |
| 選手內容來源 | **先用 M2 試跑的流派＋基準 Bot 的旋鈕變體撐起名單**／等 M5 正式軍備競賽 |
| 介面平台 | **瀏覽器（延續 M1／M3）**／直接轉 Unity |
| 比賽模擬時機 | **推進時間時一次模擬整週**／比賽日逐場模擬可觀看 |
| 狀態與老化 | **M4 不做**（企劃書建議先量測勝率分布） |
| 存檔 | **瀏覽器 localStorage 單一存檔**／檔案匯出入 |
