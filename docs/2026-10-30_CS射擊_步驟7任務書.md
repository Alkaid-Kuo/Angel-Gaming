## 一、目標

把一隻基準 Bot 變成「大量選手」：選手＝**角色（流派）＋版本＋個人習慣**，由一個確定性函式衍生出屬性包與旋鈕；屬性經驅動層真的影響強度（含反應延遲）；離線互打產生**隱藏強度表**，寫成射擊內容包，給步驟 8 的經營層與假閘道用。

### 驗收表

| 項目 | 門檻 |

## 二、設計

### 2.1 選手規格與衍生（`src/shooter/players.ts`，新檔，純函式、確定性）

```ts
export type ShooterRole = 'entry' | 'awp' | 'support' | 'anchor' | 'lurk';   // 突破手、狙擊手、支援（道具手）、錨點、游擊
export interface ShooterPlayerSpec {
  readonly role: ShooterRole;
  readonly version: number;      // 1～MAX_VERSION（建議 5）
  readonly habit: number;        // 個人習慣種子（整數；0 = 無偏移）
}
export interface DerivedPlayer {
  readonly attributes: Attributes;   // 六項 0～100 整數
  readonly knobs: KnobValues;        // 至少含 role；其他旋鈕依角色（狙擊手 awpSlot、支援 economy…）
  readonly reactionTicks: number;    // reactionTicksFor(attributes)
}
export function derivePlayer(spec: ShooterPlayerSpec): DerivedPlayer;
export function reactionTicksFor(attrs: Attributes): number;
export const ROLE_TABLE: Readonly<Record<ShooterRole, { name: string; style: string; base: Attributes; growth: Attributes }>>;
```

- **角色基準屬性**：以 6-2 報告第八節的建議為初值（突破手 aggression 70／reaction 65／movement 60／discipline 45；狙擊手 aim 75／discipline 65／aggression 35／awareness 60；支援 discipline 70／awareness 65／aggression 40；錨點 discipline 75／awareness 70／aggression 30；游擊 awareness 70／movement 65／aggression 55；沒寫的為 50）。
- **版本＝屬性成長**：版本 3 ＝ 基準；每升一版主屬性加 `growth`（每角色不同的成長向量，例：狙擊手 aim +6、reaction +3；突破手 reaction +5、aim +4；支援 awareness +5、aim +3…），版本 1、2 反向扣。**六項總和隨版本嚴格遞增**，但風格屬性（discipline、movement、aggression）的成長要小，強度主要靠 aim、reaction、awareness。
- **個人習慣**：`habit` 經 `shared/prng` 產生六項各 −4～+4 的偏移（確定性），夾回 0～100；`habit = 0` 無偏移。
- **反應延遲**：`reactionTicksFor`：初值 `5 + round((100 − reaction) / 100 × 6)`（reaction 0 → 11 tick、50 → 8、100 → 5）。這是驅動層數值，不是 API；寫進規格第十一節。Bot 內 6-1 另有「看到新目標後額外等 3→0 次決策」，兩者疊加後若 reaction 梯度太陡或太平，調 Bot 內那段，不調引擎下限。

### 2.3 角色在 Bot 裡生效（`bots/shooter-src/`，版本升 **2.1**）

6-2 的角色由隊內序號決定，旋鈕 `role` 只有 4（狙擊）有作用。步驟 7 要讓五個角色真的分工：

| 角色 | T 方 | CT 方 | 購買偏好 |
|---|---|---|---|
| 突破手 entry | 主力組第一個進、丟閃、執行時走最前 | 回防時第一個進點 | 閃 2、護甲優先 |
| 狙擊手 awp | 第二組或主力後方長距離架槍，不第一個進 | 長對線位（6-2 已有） | 錢夠買狙擊槍（隊內最多一把；兩個狙擊手時序號小的買） |
| 支援 support | 煙霧手、跟在突破手後補位、換血 | 疊點看主入口的第二人、燃燒封入口 | 煙 1 閃 1（＋燃燒） |
| 錨點 anchor | 持彈者優先人選、下包後守包 | 每點第一人、輪轉時不動 | 燃燒 1、閃 1、拆彈器優先 |
| 游擊 lurk | 第二組、default 時控另一點、fake 的佯攻組 | 中路位、輪轉時第一個動 | 閃 1、手雷 |

- 分配規則：`ctLayout`、T 分組、突破手／煙霧手、持彈者、拆彈器優先、狙擊手，全部改成**先看角色、角色重複或缺角時退回隊內序號**。五狙時只有序號最小的買狙擊槍，其餘當突破手打（但屬性還是狙擊手的，所以會弱，這是五狙輸的來源）。
- `economy.js` 的 `UTIL` 表改成依角色。
- 檔案大小：目前 190 KB。先瘦身再加：允許 `scripts/build-shooter-bots.ts` 在合成時**剝掉註解與空行**（原始碼保留註解；`--check` 比對剝過的結果），再合併重複掃描。
- 地圖無關、只讀 init 與觀察資料、亂數只用 `helpers.random()` 等規則不變。

### 2.4 強度表（`scripts/shooter-strength.ts` 產生，確定性、可重跑）

強度單位＝Elo（給經營層 `expectedPermille` 用），**定義**：

- 參照隊 R ＝ 均衡陣容（五角色各一、版本 3、habit 0）。
- **版本成長** `growth(v)`：均衡陣容版本 v 對 R，兩張圖各 20 場雙邊（80 場），由勝率反推 Elo 差；v＝3 為 0。
- **角色偏移** `roleOffset(r)`：不用「換一人對 R」（只動 1/5、噪音大）也不用「五個同角色對 R」（五狙那種人為弱隊會低估角色）。**定案**：隊伍 X(r) ＝ 均衡陣容但角色 r 升到版本 5，五支 X(r) 兩兩互打（10 組、各 40 場），用 Bradley–Terry 解出五個角色「升兩版的價值」，換算成每版的偏移；角色基礎值一律 1500。這樣角色分數反映「這個角色升版對隊伍的貢獻」，正是經營層買人時要的資訊。
- `power(r, v) = 1500 + growth(v) + roleOffset(r) × (v − 3)`，再做**單調化**（每個角色隨版本嚴格遞增，最小間隔 10），報告列原始量測值與最後採用值。
- **整場 Elo 與回合勝率的關係**：整場勝率很快飽和（6-2 對陪練 97%），所以量測一律用**回合勝率**，另外用同一批資料擬合「回合勝率 → 整場勝率」的映射（一條 logistic），強度表的 Elo 以**整場**為準（經營層一場比賽一個勝負）。報告要列擬合結果。
- 驗證：隨機抽 10 組不同名單（角色、版本混搭，含 habit ≠ 0），實打 20 場，與強度表（隊伍 power ＝ 五人平均）預測的勝率比，平均誤差 ≤ 8 個百分點。
- 計算量提示：一場約 6～9 秒；`scripts/shooter-eval.ts` 的 worker 機制可以重用，`--jobs 4` 以下；長跑放背景、輸出 JSON 到 `out/shooter-strength/`（不進版控），最後的表貼進內容包。

### 2.5 射擊內容包（`src/manage/content-shooter.ts`）

- `SHOOTER_CONTENT: ContentPack`：`id: 'shooter-1'`、`formatId` 先填 `'shooter-mr12'`（步驟 8 的閘道會宣告這個 id）、`lineages` 五個角色（`id` 用 `ShooterRole`、`name` 中文、`style` 一句話、`power` 由強度表來，長度＝MAX_VERSION）、`personas`／`economy`／名字庫先**沿用** `STUB_CONTENT` 的值（註明「暫代，步驟 8／9 審」）、`teamNames` 另取七個射擊風格的隊名、`humanTeamName` 沿用。

## 三、測試

### 單元（`test/shooter-players.test.ts`）

- 衍生確定性（同 spec 兩次相同；habit 不同至少一項不同；habit 0 無偏移）；屬性範圍；版本 1～MAX 六項總和嚴格遞增；每角色主屬性在版本 MAX 不超過 100。
- `reactionTicksFor`：0／50／100 的值；永遠 ≥ 5。
- runner：給 `attributes` 後 `InitData.attributes` 與 `rules.reactionTicks` 正確；沒給就是 50 與預設；人類控制器仍 0；同種子同名單雜湊相同。
- 內容包：五個 lineage、power 長度一致、嚴格遞增、`expectedPermille` 可用。

### 角色情境（加進 `src/shooter/ai-scenarios.ts`，每條 5 種子、兩張圖）

| 編號 | 情境 | 判定 |
|---|---|---|
| R1 | 突破手第一個進點 | T split／rush：第一個進包點的人 `role = entry`（≥ 4／5 種子） |
| R2 | 狙擊手不第一個進、架長線 | 同上：狙擊手進點順序 ≥ 3，執行前有開鏡 ≥ 2 秒 |
| R3 | 支援丟煙 | T 執行前的煙由 `role = support` 丟 |
| R4 | 錨點不輪轉 | T2 佈置（B 有接觸）：A 的錨點仍在 A 守點位 9 步內；A 的非錨點有人往 B |
| R5 | 游擊走第二組／中路 | default：游擊在另一點的待命格；CT：游擊在中路位 |
| R6 | 五狙退化 | 五個 `role = awp`：只有一把狙擊槍、其餘買步槍、仍能執行計畫（不卡） |

### 梯度與強度（`scripts/shooter-gradient.ts`，報告附表；不進 vitest，耗時）

- 四個強度屬性 × 四檔、兩個風格屬性 × 兩檔、版本 1～5 × 均衡、五狙對均衡、強度表驗證 10 組。全部用**對照組＝全 50 基準（habit 0）**或均衡版本 3，兩張圖各半、雙邊、種子固定、輸出 JSON。
